Tài liệu cấu hình OpenIddict trên IIS cho mạng nội bộ

Hướng dẫn xử lý lỗi System.Security.Cryptography.CryptographicException: Access is denied khi chạy AuthServer/OpenIddict trên IIS.

1. Mô tả lỗi

Khi deploy ứng dụng ASP.NET Core sử dụng OpenIddict lên IIS, hệ thống phát sinh lỗi:

System.Security.Cryptography.CryptographicException: Access is denied.
at System.Security.Cryptography.X509Certificates.X509Store.Open(OpenFlags flags)
at Microsoft.Extensions.DependencyInjection.OpenIddictServerBuilder
    .AddDevelopmentEncryptionCertificate(...)

Lỗi thường xuất hiện khi request đi qua các endpoint như:

  • /connect/authorize
  • /connect/token
  • /connect/introspect

2. Nguyên nhân

Trong cấu hình hiện tại, ứng dụng đang dùng:

options.AddDevelopmentEncryptionCertificate()
       .AddDevelopmentSigningCertificate();

Hai hàm này dùng certificate phát triển của OpenIddict và cần truy cập vào Windows Certificate Store. Khi chạy dưới IIS, App Pool Identity thường không có quyền mở certificate store hoặc private key, nên phát sinh lỗi Access is denied.

Không nên dùng AddDevelopmentEncryptionCertificate() và AddDevelopmentSigningCertificate() khi deploy lên IIS, kể cả trong mạng nội bộ.

3. Giải pháp nhanh cho mạng nội bộ

Nếu hệ thống chỉ dùng trong mạng nội bộ và đang ở giai đoạn test, có thể dùng Ephemeral Key:

if (builder.Environment.IsDevelopment())
{
    options.AddDevelopmentEncryptionCertificate()
           .AddDevelopmentSigningCertificate();
}
else
{
    options.AddEphemeralEncryptionKey()
           .AddEphemeralSigningKey();
}

options.DisableAccessTokenEncryption();
Lưu ý: Ephemeral Key được tạo trong bộ nhớ. Khi restart IIS/App Pool, key sẽ thay đổi và token cũ có thể không còn hợp lệ. Người dùng có thể phải đăng nhập lại.

4. Cấu hình OpenIddict hoàn chỉnh đề xuất

builder.Services.AddOpenIddict()
    .AddCore(options =>
    {
        options.UseEntityFrameworkCore()
               .UseDbContext<ApplicationDbContext>();
    })
    .AddServer(options =>
    {
        // Endpoints
        options.SetAuthorizationEndpointUris("/connect/authorize")
               .SetTokenEndpointUris("/connect/token")
               .SetEndSessionEndpointUris("/connect/endsession")
               .SetIntrospectionEndpointUris("/connect/introspect");

        // Flows
        options.AllowAuthorizationCodeFlow()
               .AllowRefreshTokenFlow()
               .RequireProofKeyForCodeExchange();

        // Scopes
        options.RegisterScopes(
            OpenIddictConstants.Scopes.OpenId,
            OpenIddictConstants.Scopes.Email,
            OpenIddictConstants.Scopes.Profile,
            OpenIddictConstants.Scopes.Roles,
            OpenIddictConstants.Scopes.OfflineAccess,
            "api"
        );

        // Token lifetimes
        options.SetAccessTokenLifetime(TimeSpan.FromMinutes(
            builder.Configuration.GetValue<int>("Auth:AccessTokenLifetimeMinutes", 15)));

        options.SetRefreshTokenLifetime(TimeSpan.FromDays(
            builder.Configuration.GetValue<int>("Auth:RefreshTokenExpiryDays", 30)));

        options.SetIdentityTokenLifetime(TimeSpan.FromMinutes(60));

        // Signing & encryption
        if (builder.Environment.IsDevelopment())
        {
            options.AddDevelopmentEncryptionCertificate()
                   .AddDevelopmentSigningCertificate();
        }
        else
        {
            options.AddEphemeralEncryptionKey()
                   .AddEphemeralSigningKey();
        }

        // JWT access token không mã hóa, để API khác có thể đọc/validate
        options.DisableAccessTokenEncryption();

        options.UseAspNetCore()
               .EnableAuthorizationEndpointPassthrough()
               .EnableTokenEndpointPassthrough()
               .EnableEndSessionEndpointPassthrough()
               .EnableStatusCodePagesIntegration()
               .DisableTransportSecurityRequirement();
    })
    .AddValidation(options =>
    {
        options.UseLocalServer();
        options.UseAspNetCore();
    });

5. So sánh các lựa chọn

Cách cấu hình Phù hợp Ưu điểm Nhược điểm
AddDevelopment... Chạy local bằng Visual Studio Dễ dùng khi phát triển Dễ lỗi quyền trên IIS, không nên dùng khi deploy
AddEphemeral... Mạng nội bộ, test, demo Không cần certificate, chạy nhanh trên IIS Restart app làm token cũ mất hiệu lực
AddSigningCertificate(...) Nội bộ production Ổn định, restart không mất token Cần quản lý file certificate/password

6. Cấu hình tốt hơn cho nội bộ production

Nếu hệ thống AuthServer dùng thật cho nhiều app như EMR, HRM, Report, nên dùng certificate dạng file .pfx.

options.AddEncryptionCertificate(new X509Certificate2(
    @"D:\Certificates\openiddict-encryption.pfx",
    builder.Configuration["Auth:Certificates:EncryptionPassword"],
    X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
));

options.AddSigningCertificate(new X509Certificate2(
    @"D:\Certificates\openiddict-signing.pfx",
    builder.Configuration["Auth:Certificates:SigningPassword"],
    X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
));

Ví dụ cấu hình trong appsettings.Production.json:

{
  "Auth": {
    "AccessTokenLifetimeMinutes": 15,
    "RefreshTokenExpiryDays": 30,
    "Certificates": {
      "EncryptionPassword": "your-encryption-cert-password",
      "SigningPassword": "your-signing-cert-password"
    }
  }
}
Với hệ thống nội bộ dùng thật, nên dùng certificate .pfx thay vì Ephemeral Key để đảm bảo token ổn định sau khi restart server.

7. Lưu ý về HTTPS trong mạng nội bộ

Hiện tại code có:

options.UseAspNetCore().DisableTransportSecurityRequirement();

Cấu hình này cho phép chạy qua HTTP, phù hợp khi test bằng IP nội bộ như:

http://192.168.1.10:5000
Tuy nhiên, nếu AuthServer dùng thật cho nhiều ứng dụng nội bộ, vẫn nên cấu hình HTTPS bằng certificate nội bộ để bảo vệ cookie, authorization code và refresh token.

8. Checklist sau khi sửa

  • Đổi AddDevelopment... sang AddEphemeral... hoặc certificate .pfx.
  • Publish lại AuthServer.
  • Restart IIS App Pool.
  • Mở lại endpoint /connect/.well-known/openid-configuration nếu có cấu hình discovery.
  • Test login lại từ frontend Angular.
  • Nếu dùng Ephemeral Key, yêu cầu user đăng nhập lại sau khi restart app.

9. Kết luận

Với hệ thống chỉ dùng trong mạng nội bộ:

  • Test/demo: dùng AddEphemeralEncryptionKey() và AddEphemeralSigningKey().
  • Chạy thật: dùng certificate .pfx riêng cho signing và encryption.
  • Không nên dùng: AddDevelopmentEncryptionCertificate() khi deploy IIS.
