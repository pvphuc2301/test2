Hướng dẫn tạo Private CA bằng OpenSSL cho IIS và OpenIddict

Tài liệu triển khai HTTPS nội bộ cho AuthServer, EMR, HRM, Report và phân biệt với certificate dùng để ký JWT trong OpenIddict.

Mục lục

1. Mục tiêu triển khai

Tài liệu này hướng dẫn tạo một Private Certificate Authority bằng OpenSSL để cấp HTTPS certificate cho hệ thống nội bộ.

Phù hợp cho:

  • AuthServer dùng OpenIddict
  • EMR chạy trên IIS
  • HRM chạy trên IIS
  • Report Server
  • Angular frontend gọi API qua HTTPS nội bộ
Private CA giúp trình duyệt và ứng dụng tin tưởng certificate nội bộ sau khi import Root CA vào máy client.

2. Mô hình hệ thống

Root CA nội bộ
   │
   ├── auth.hospital.local   → IIS AuthServer / OpenIddict
   ├── emr.hospital.local    → IIS EMR
   ├── hrm.hospital.local    → IIS HRM
   └── report.hospital.local → IIS Report
Thành phần Certificate sử dụng Mục đích
IIS HTTPS Certificate Cert do Root CA nội bộ cấp Mã hóa kết nối HTTPS giữa browser và server
OpenIddict Signing Certificate PFX riêng Ký JWT token
OpenIddict Encryption Certificate PFX riêng hoặc disable access token encryption Mã hóa token nếu cần
HTTPS certificate của IIS và Signing certificate của OpenIddict là hai loại khác nhau. Không nên dùng lẫn lộn nếu triển khai production nội bộ.

3. Cài OpenSSL trên Windows

Cài OpenSSL bản Win64. Sau khi cài, mở CMD hoặc PowerShell và kiểm tra:

openssl version

Nếu hiển thị phiên bản OpenSSL, nghĩa là đã cài thành công.

Tạo thư mục làm việc

mkdir D:\OpenSSL-CA
cd /d D:\OpenSSL-CA

mkdir certs
mkdir private
mkdir csr
mkdir server

Cấu trúc thư mục:

D:\OpenSSL-CA
│
├── certs
├── private
├── csr
└── server

4. Tạo Root CA

Bước 1: Tạo private key cho Root CA

openssl genrsa -out private/rootCA.key 4096

File sinh ra:

D:\OpenSSL-CA\private\rootCA.key
File rootCA.key là khóa riêng của CA. Không copy lung tung, không gửi cho client, không để trong thư mục public.

Bước 2: Tạo Root CA certificate

openssl req -x509 -new -nodes ^
-key private/rootCA.key ^
-sha256 ^
-days 3650 ^
-out certs/rootCA.crt

Khi được hỏi thông tin, có thể nhập ví dụ:

Country Name: VN
State or Province Name: HCM
Locality Name: HCM
Organization Name: Hospital
Organizational Unit Name: IT
Common Name: Hospital Root CA

Kết quả:

D:\OpenSSL-CA\certs\rootCA.crt
D:\OpenSSL-CA\private\rootCA.key

5. Import Root CA vào máy trạm

Để browser tin tưởng certificate do CA nội bộ cấp, cần import file:

D:\OpenSSL-CA\certs\rootCA.crt

Vào store:

Trusted Root Certification Authorities

Import trên Windows

  1. Mở certlm.msc bằng quyền Administrator.
  2. Chọn Trusted Root Certification Authorities.
  3. Chọn Certificates.
  4. Right click → All Tasks → Import.
  5. Chọn file rootCA.crt.
Sau khi import Root CA, các certificate do Root CA này cấp sẽ được Windows và browser tin tưởng.

6. Cấp SSL certificate cho AuthServer

Ví dụ domain nội bộ:

auth.hospital.local
IP: 192.168.1.10

Bước 1: Tạo private key cho AuthServer

openssl genrsa -out server/auth.key 2048

Bước 2: Tạo CSR

openssl req -new ^
-key server/auth.key ^
-out csr/auth.csr

Khi hỏi Common Name, nhập:

auth.hospital.local

Bước 3: Tạo file SAN config

Tạo file:

D:\OpenSSL-CA\server\auth.ext

Nội dung:

authorityKeyIdentifier=keyid,issuer
basicConstraints=CA:FALSE
keyUsage=digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=@alt_names

[alt_names]
DNS.1=auth.hospital.local
DNS.2=localhost
IP.1=192.168.1.10
SAN rất quan trọng. Nếu thiếu SAN hoặc domain/IP không khớp, browser sẽ báo lỗi certificate name invalid.

Bước 4: Ký certificate bằng Root CA

openssl x509 -req ^
-in csr/auth.csr ^
-CA certs/rootCA.crt ^
-CAkey private/rootCA.key ^
-CAcreateserial ^
-out server/auth.crt ^
-days 825 ^
-sha256 ^
-extfile server/auth.ext

Bước 5: Tạo PFX cho IIS

openssl pkcs12 -export ^
-out server/auth.pfx ^
-inkey server/auth.key ^
-in server/auth.crt

Nhập password cho file PFX. Password này dùng khi import certificate vào IIS.

7. Import PFX và bind HTTPS trong IIS

Import certificate

  1. Mở IIS Manager.
  2. Chọn server.
  3. Mở Server Certificates.
  4. Chọn Import.
  5. Chọn file auth.pfx.
  6. Nhập password đã tạo.

Bind HTTPS cho site AuthServer

  1. Chọn site AuthServer.
  2. Chọn Bindings.
  3. Chọn Add.
  4. Type: https.
  5. Host name: auth.hospital.local.
  6. SSL certificate: chọn certificate vừa import.

Cấu hình hosts file nếu chưa có DNS nội bộ

Mở file:

C:\Windows\System32\drivers\etc\hosts

Thêm:

192.168.1.10 auth.hospital.local

Kiểm tra

https://auth.hospital.local

Nếu cấu hình đúng, browser sẽ không còn cảnh báo certificate.

8. Cấp cert cho EMR, HRM, Report

Thực hiện tương tự với từng domain.

App Domain IP ví dụ
AuthServer auth.hospital.local 192.168.1.10
EMR emr.hospital.local 192.168.1.11
HRM hrm.hospital.local 192.168.1.12
Report report.hospital.local 192.168.1.13

Ví dụ file SAN cho EMR

authorityKeyIdentifier=keyid,issuer
basicConstraints=CA:FALSE
keyUsage=digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=@alt_names

[alt_names]
DNS.1=emr.hospital.local
IP.1=192.168.1.11

9. OpenIddict Signing Certificate

Certificate dùng cho IIS HTTPS không bắt buộc phải là certificate dùng để ký JWT. Với OpenIddict, nên tạo riêng signing certificate.

Tạo signing certificate bằng OpenSSL

openssl req -x509 -newkey rsa:2048 ^
-keyout server/openiddict-signing.key ^
-out server/openiddict-signing.crt ^
-days 3650 ^
-nodes ^
-subj "/CN=OpenIddict Signing Certificate"

Tạo PFX

openssl pkcs12 -export ^
-out server/openiddict-signing.pfx ^
-inkey server/openiddict-signing.key ^
-in server/openiddict-signing.crt

Cấu hình trong OpenIddict

options.AddSigningCertificate(
    new X509Certificate2(
        @"D:\Certificates\openiddict-signing.pfx",
        "your-password",
        X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
    )
);

options.DisableAccessTokenEncryption();
Nếu chỉ dùng JWT access token và muốn API đọc token dễ hơn, có thể dùng DisableAccessTokenEncryption(). Khi đó nên đảm bảo hệ thống chạy HTTPS.

10. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
NET::ERR_CERT_AUTHORITY_INVALID Máy client chưa trust Root CA Import rootCA.crt vào Trusted Root Certification Authorities
SSL_ERROR_BAD_CERT_DOMAIN Domain truy cập không có trong SAN Thêm đúng DNS/IP vào file .ext rồi ký lại cert
Access is denied khi OpenIddict mở cert IIS App Pool không có quyền đọc certificate store/private key Dùng PFX với EphemeralKeySet hoặc cấp quyền đọc private key
invalid issuer Authority cấu hình sai hoặc khác URL đang chạy Đồng bộ URL AuthServer trong backend/frontend
Cookie không lưu HTTP, SameSite/Secure không đúng Dùng HTTPS và cấu hình cookie Secure

11. Khuyến nghị triển khai

Cho test nội bộ

  • Dùng OpenSSL Root CA.
  • Import Root CA thủ công vào máy test.
  • Cấp certificate cho AuthServer, EMR, HRM.

Cho production nội bộ

  • Dùng DNS nội bộ thay vì hosts file.
  • Quản lý Root CA key cẩn thận.
  • Không đặt private key trong thư mục web public.
  • Tạo riêng OpenIddict signing certificate.
  • Không dùng AddDevelopmentEncryptionCertificate() khi deploy IIS.
  • Nên ghi lại ngày hết hạn certificate để gia hạn trước.

Cấu hình OpenIddict khuyên dùng

if (builder.Environment.IsDevelopment())
{
    options.AddDevelopmentEncryptionCertificate()
           .AddDevelopmentSigningCertificate();
}
else
{
    options.AddSigningCertificate(
        new X509Certificate2(
            @"D:\Certificates\openiddict-signing.pfx",
            builder.Configuration["Auth:Certificates:SigningPassword"],
            X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
        )
    );

    options.DisableAccessTokenEncryption();
}
Với hệ thống EMR/HRM/AuthServer nội bộ, mô hình tốt là: OpenSSL Root CA cho HTTPS nội bộ, và PFX riêng cho OpenIddict signing.
