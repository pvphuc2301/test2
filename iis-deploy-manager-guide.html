IIS Deploy Manager

IIS Deploy Manager is an enterprise-grade deployment coordinator designed to build, package, backup, deploy, and verify IIS web applications. Supporting both a lightweight Command Line Interface (CLI) for CI/CD pipelines and a modern visual dashboard (WPF) for manual management, it enables rolling or parallel multi-server deployments with automatic rollbacks.

💡 Key Capabilities
  • Supports ASP.NET Core, Angular, and Static HTML applications.
  • Remote deployments using secure PowerShell Remoting (WinRM) or SSH.
  • Environment variable credential expansion to prevent commit of plaintext secrets.
  • Automatic rollback of all servers in a deployment group if any server fails its health check.
  • Modal approvals workflow before bringing application servers offline.

Quick Start Guide

Deploy your first application in minutes by setting up a local configuration file.

1. Prepare the Configuration

Create a file named deploy-config.json in your project directory:

deploy-config.json 
{
  "apps": [
    {
      "name": "My Web API",
      "type": "aspnetcore",
      "environment": "production",
      "sourcePath": "C:\\Projects\\MyWebAPI",
      "publishPath": "C:\\Publish\\MyWebAPI",
      "deployPath": "C:\\inetpub\\wwwroot\\myapi",
      "siteName": "MyWebApiSite",
      "appPoolName": "MyWebApiPool",
      "backupPath": "C:\\Backups\\MyWebAPI",
      "healthCheckUrl": "http://localhost/health",
      "requireApproval": false
    }
  ]
}

2. Run Deployment

Open a terminal (PowerShell or Command Prompt) and execute the CLI deployer:

Command Line 
# Build, publish, backup, deploy, and verify the application
dotnet run --project IISDeployManager -- deploy "My Web API"
# Deploy while bypassing the build and publish steps
dotnet run --project IISDeployManager -- deploy "My Web API" --skip-build

Configuring Applications

Application configurations are stored in JSON. Every application schema in the apps array contains the following fields:

Field Name Type Default/Allowed Description
name String Required Unique, user-friendly name identifying the application.
type String aspnetcore, angular, static The project framework. Controls the default build and publish command sequence.
environment String Required Deploy target stage (e.g. production, staging, test).
sourcePath String Required Local filesystem directory containing the application source files.
publishPath String Required Local workspace path where compiled/built files are assembled before copying.
deployPath String Required Destination filesystem directory on target environment (IIS physical path).
siteName String Required IIS Website Name used to check website status and health.
appPoolName String Required IIS Application Pool name (is stopped during copies to prevent file locking).
backupPath String Required Root folder where prior backup archives will be stored.
exclude Array<Str> [] Array of relative filenames/folders to exclude during replication (e.g., Logs).
healthCheckUrl String null URL to query via HTTP GET to verify successful startup (returns HTTP 200).
requireApproval Boolean false If true, pauses the deployment and prompts for manual approval before taking pool offline.
deploymentStrategy String sequential, parallel Defines rolling (sequential) or parallel execution across multiple remote target servers.
servers Array<Obj> [] A list of target servers. If empty, the tool executes locally (localhost).

CLI Command Reference

The CLI provides a set of command-line operations designed to integrate with build pipelines or execute rapid management operations.

Commands

  • deploy <app-name> [--skip-build] [--config <path>]: Deploys the designated application.
  • rollback <app-name> --version <version-id> [--config <path>]: Performs rollback of the website on all nodes.
  • status <app-name> [--config <path>]: Pulls health check status, running versions, and deployment history.
  • list: Lists all applications declared in the configuration file.
CLI Examples 
# Query the current version and deployment history of an API
dotnet run --project IISDeployManager -- status "EMR API"
# Revert "EMR API" to the specific backup version timestamp
dotnet run --project IISDeployManager -- rollback "EMR API" --version EMR_API_20260522_143000

WPF Dashboard

The desktop application `IISDeployManager.Wpf` provides an administrative graphical interface suited for operations groups.

Dashboard Tabs

  1. Dashboard: Allows selecting applications, launching deployments (with a skip-build checkbox option), displaying status attributes (active version, health checks, and last messages), and initiating rollbacks by double-clicking or selecting prior versions in the history table.
  2. Configuration Editor: Offers full CRUD controls for editing applications without editing JSON files directly. It features validation prompts, strategy setup controls, and a direct target servers JSON input editor.
  3. Live Console Logs: Displays a real-time console log stream captured from the underlying deployment engines, complete with levels, server addresses, and scroll-to-end features.

Remote Target Connections

IIS Deploy Manager supports remote targets by mapping servers configs to different connection engines. Add remote servers using the following properties:

Server Schema Configuration 
{
  "address": "192.168.1.50",
  "connectionType": "winrm", // "local", "winrm", or "ssh"
  "username": "Administrator",
  "password": "%IIS_PROD_PASSWORD%", // Expanded dynamically from env variables
  "winrmPort": 5985,                 // Optional (default: 5985 / 5986)
  "sshKeyPath": null                 // Optional path to private key (for SSH connection)
}

Supported Channels

  • WinRM (Windows Remote Management): Standard channels utilizing PowerShell Remoting. Best suited for remote Windows servers. Requires target host to have WS-Management enabled (winrm quickconfig).
  • SSH (Secure Shell): Executes commands over standard SSH connections. Used for cross-platform replication or filesystems. Relies on SSH.NET. Copying uses SFTP to upload zip packages, extracting remotely via unzip, and deleting the archive.
  • Local: If servers list is empty, default local command prompt execution is used on localhost.

Manual Approvals Workflow

When deploying to sensitive environments (e.g. production), you can prevent automated failures or unscheduled downtime by enabling approvals.

⚠️ Approval Execution Point

If "requireApproval": true is set, the build and publish steps run first. Right before the pipeline shuts down the target IIS App Pool and initiates backup scripts, the pipeline pauses and prompts for approval. This guarantees that if the project fails to compile, it fails gracefully without affecting active services.

Interactive Displays

  • CLI Interface: Blocks execution and prints a highlighted prompt Deployment of "App Name" requires approval. Approve? (y/n):. Pressing y resumes execution; other inputs abort the run.
  • WPF GUI Dashboard: Automatically switches log panels and pops up a modal approval card. It displays the target environment details, deployment strategy, project type, and lists all targeted servers, prompting confirmation via "APPROVE & DEPLOY" or "REJECT DEPLOYMENT" actions.

Technical Architecture

The codebase is written in C# .NET 8.0, partitioned into a core execution engine library and two client projects sharing identical services.

🏗️ Project Layout
  • IISDeployManager.csproj (Core & CLI): Defines command processors, configuration loading, pipeline flows, and CLI interfaces.
  • IISDeployManager.Wpf.csproj (UI Client): Implements the WPF GUI desktop workspace and visual configuration forms.
  • Config file paths: Both modules automatically search parent directories up to 5 levels to locate deploy-config.json, maintaining unified database coordination.

Execution Abstraction

To support multiple deployment protocols seamlessly, all filesystem, execution, and copying interactions are routed through the ICommandExecutor interface.

ICommandExecutor.cs 
public interface ICommandExecutor : IDisposable
{
    Task<(bool Success, string Output)> RunCommandAsync(string command, string? workingDirectory = null);
    Task CopyFilesAsync(string localSourcePath, string remoteDestPath, List<string> excludePatterns);
    Task DirectoryExistsAsync(string path);
    Task FileExistsAsync(string path);
    Task CreateDirectoryAsync(string path);
}

Implementation Details

  • LocalExecutor: Hooks into System.Diagnostics.Process to run local commands on cmd.exe. Implements local directory and copy operations.
  • WinRmExecutor: Encapsulates remote PowerShell execution, dynamically converting string passwords to SecureString. Executes tasks via Invoke-Command -Session and uses Copy-Item -ToSession for copying.
  • SshExecutor: Integrates SSH.NET's SshClient and SftpClient. Runs shell commands directly. Copied files are zipped locally, uploaded via SFTP, and unzipped on the target server.

Rollback Mechanics

Rollbacks are triggered either manually through command scripts and dashboard events, or automatically when a multi-server deploy encounters a failure.

Automatic Rollback Workflow

  1. The pipeline deploys to target servers according to the strategy.
  2. If the health check fails on Server N (or any server in parallel mode), the deployment halts.
  3. The pipeline invokes the rollback workflow on all servers where the deployment completed successfully.
  4. On each target server, the executor stops the app pool, restores the backup directory corresponding to the backup ID, and restarts the app pool.
  5. A post-rollback health check verifies the status of the restored application.

Secrets & Security

Protecting credentials is a priority. Plaintext secrets should never be checked into code repositories.

Environment Variables Configuration Example 
{
  "address": "web-prod-01",
  "connectionType": "winrm",
  "username": "%IIS_DEPLOY_USER%",
  "password": "%IIS_DEPLOY_PASSWORD%"
}

Upon parsing configuration profiles, the DeploymentService invokes Environment.ExpandEnvironmentVariables, translating placeholders into environment variables stored on the executing system.

Log Streaming Sink

To support real-time logging in WPF without causing locks or application lag, a custom logging channel is implemented.

WpfLogSink.cs

The WpfLogSink implements Serilog's ILogEventSink:

  • Pipes log lines out through a static C# event handler (OnLogMessage).
  • Utilizes Dispatcher.BeginInvoke to safely marshal updates onto the WPF GUI thread without blocking background tasks.
  • Implements buffer limiting: when the text lines exceed 2,000, it automatically discards the oldest 500 lines to prevent memory bloat.

Troubleshooting & FAQs

❌ WinRM Connection Failures

Symptom: Connection fails with credentials errors or "Access Denied" during Invoke-Command.

Solution: WinRM requires administrative privileges on target machines. Enable WS-Management on the target machine (winrm quickconfig) and add the target IP to TrustedHosts if executing in non-domain configurations: Set-Item WSMan:\localhost\Client\TrustedHosts -Value <IP-Address> -Force.

❌ SSH File Locking / Access Denied

Symptom: Copy fails on remote SSH targets or folder unzip is blocked.

Solution: Ensure the user has write permissions to the deployment folder on the target Linux/Windows system. For Linux servers, verify that the unzip tool is installed, as it is required to extract SFTP zip packages.

⚠️ IIS App Pool Locking Files

Symptom: Copied binaries (DLLs) fail to copy due to locked files, even though App Pool stop commands succeeded.

Solution: WinRM or local executors sometimes return before the IIS App Pool process (w3wp.exe) has fully terminated. The pipeline includes an automatic delay, but for large applications, configure the app pool's shutdown limit settings to allow faster termination.
