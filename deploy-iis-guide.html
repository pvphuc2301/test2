Hướng dẫn Deploy C# / ASP.NET Core và Angular lên IIS

Tài liệu thực hành triển khai ứng dụng lên IIS: chuẩn bị môi trường, publish backend C#, publish Angular, cấu hình IIS, xử lý routing SPA, cấu hình API, log, quyền thư mục và các lỗi thường gặp.

Mục lục

1. Tổng quan mô hình deploy 2. Chuẩn bị IIS Server 3. Publish C# / ASP.NET Core 4. Publish Angular 5. Tạo IIS Site cho Backend 6. Tạo IIS Site cho Angular 7. Cấu hình appsettings / environment 8. Log và kiểm tra sau deploy 9. Lỗi thường gặp và cách khắc phục 10. Checklist triển khai

1. Tổng quan mô hình deploy

Một hệ thống web nội bộ hoặc EMR thường có 2 phần:

Backend C# / ASP.NET Core

Chạy API, nghiệp vụ, xác thực, kết nối database, file storage, background job.

Ví dụ URL:

https://api.company.local

Frontend Angular

Ứng dụng SPA chạy HTML, CSS, JS static. Gọi API qua HTTP/HTTPS.

Ví dụ URL:

https://emr.company.local
Khuyến nghị: Nên deploy backend và frontend thành 2 IIS Site riêng biệt. Cách này dễ cấu hình SSL, CORS, log, recycle app pool và scale sau này.

2. Chuẩn bị IIS Server

2.1. Bật IIS trên Windows

  1. Mở Turn Windows features on or off.
  2. Bật Internet Information Services.
  3. Bật thêm các mục:
  • Web Management Tools → IIS Management Console
  • World Wide Web Services → Common HTTP Features → Static Content
  • World Wide Web Services → Application Development Features → ASP.NET, .NET Extensibility, ISAPI Extensions, ISAPI Filters
  • Security → Request Filtering

2.2. Cài .NET Hosting Bundle

Với ASP.NET Core chạy trên IIS, server cần cài đúng .NET Hosting Bundle. Hosting Bundle chứa ASP.NET Core Runtime và ASP.NET Core Module để IIS có thể khởi động ứng dụng.

Nếu máy server chỉ cài .NET SDK nhưng chưa cài Hosting Bundle, ứng dụng ASP.NET Core vẫn có thể lỗi khi chạy trên IIS.

2.3. Cài IIS URL Rewrite

Angular SPA cần URL Rewrite để khi người dùng refresh trực tiếp các route như /benh-an/123, IIS sẽ trả về index.html thay vì báo 404.

2.4. Tạo thư mục deploy

D:\Sites\MyApp\Api
D:\Sites\MyApp\Web
D:\Sites\MyApp\Logs
D:\Sites\MyApp\Files

Nên tách thư mục source code, publish output, log và file upload.

3. Publish C# / ASP.NET Core

3.1. Publish bằng CLI

dotnet restore
dotnet build -c Release
dotnet publish -c Release -o D:\Publish\MyApi

3.2. Publish self-contained cho Windows x64

dotnet publish -c Release -r win-x64 --self-contained true -o D:\Publish\MyApi

Dùng self-contained khi server không muốn phụ thuộc nhiều vào runtime đã cài sẵn. Tuy nhiên dung lượng publish sẽ lớn hơn.

3.3. Publish framework-dependent

dotnet publish -c Release -o D:\Publish\MyApi

Cách này nhẹ hơn, nhưng server phải cài đúng .NET Runtime / Hosting Bundle tương ứng.

3.4. File cần có sau publish

MyApi.dll
MyApi.exe                 nếu self-contained hoặc apphost enabled
appsettings.json
appsettings.Production.json
web.config
wwwroot\                  nếu backend có static file

3.5. Chạy thử trước khi đưa vào IIS

cd D:\Publish\MyApi
dotnet MyApi.dll

Nếu chạy thành công bằng CLI nhưng lỗi trên IIS, vấn đề thường nằm ở IIS, quyền thư mục, Hosting Bundle, app pool hoặc web.config.

4. Publish Angular

4.1. Build production

npm install
ng build -c production

Hoặc nếu project có script:

npm run build:prod

4.2. Xác định output folder

Tùy phiên bản Angular và cấu hình project, output có thể là:

dist/my-app
hoặc
/dist/my-app/browser

Thư mục cần copy lên IIS là thư mục chứa file index.html.

4.3. Build khi deploy vào subfolder

Nếu ứng dụng chạy tại:

https://domain.com/emr/

Build với base href:

ng build -c production --base-href /emr/

4.4. web.config cho Angular SPA

Tạo file web.config cùng cấp với index.html:

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="Angular Routes" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/" />
        </rule>
      </rules>
    </rewrite>

    <staticContent>
      <remove fileExtension=".json" />
      <mimeMap fileExtension=".json" mimeType="application/json" />
      <remove fileExtension=".webmanifest" />
      <mimeMap fileExtension=".webmanifest" mimeType="application/manifest+json" />
    </staticContent>
  </system.webServer>
</configuration>
Nếu deploy Angular vào subfolder như /emr/, rule rewrite nên đổi thành <action type="Rewrite" url="/emr/" /> hoặc cấu hình IIS Application đúng theo subfolder.

5. Tạo IIS Site cho Backend ASP.NET Core

5.1. Tạo Application Pool

  1. Mở IIS Manager.
  2. Vào Application Pools → Add Application Pool.
  3. Name: MyApiPool.
  4. .NET CLR Version: No Managed Code.
  5. Managed pipeline mode: Integrated.
ASP.NET Core tự chạy trong Kestrel phía sau IIS, vì vậy App Pool nên để No Managed Code.

5.2. Tạo Website

  1. Sites → Add Website.
  2. Site name: MyApi.
  3. Application Pool: MyApiPool.
  4. Physical path: D:\Sites\MyApp\Api.
  5. Binding: https://api.company.local hoặc port riêng.

5.3. Copy publish output

xcopy D:\Publish\MyApi D:\Sites\MyApp\Api /E /Y

5.4. Cấp quyền thư mục

Cấp quyền cho identity của App Pool:

IIS AppPool\MyApiPool

Các quyền thường cần:

  • Read & Execute cho thư mục deploy.
  • Modify cho thư mục log, upload, file storage.

6. Tạo IIS Site cho Angular

6.1. Tạo Application Pool

Angular chỉ là static file, có thể tạo App Pool riêng:

Name: MyWebPool
.NET CLR Version: No Managed Code

6.2. Tạo Website

  1. Sites → Add Website.
  2. Site name: MyWeb.
  3. Physical path: D:\Sites\MyApp\Web.
  4. Binding: https://emr.company.local.

6.3. Copy Angular build output

xcopy D:\AngularProject\dist\my-app\browser D:\Sites\MyApp\Web /E /Y

Nhớ copy cả file web.config vào cùng cấp với index.html.

7. Cấu hình appsettings / environment

7.1. Backend appsettings.Production.json

{
  "ConnectionStrings": {
    "Default": "Server=SQL-SERVER;Database=MyDb;User Id=sa;Password=your_password;TrustServerCertificate=True"
  },
  "App": {
    "SelfUrl": "https://api.company.local",
    "CorsOrigins": "https://emr.company.local"
  },
  "FileStorage": {
    "RootPath": "D:\\Sites\\MyApp\\Files"
  }
}

7.2. Angular environment production

export const environment = {
  production: true,
  apis: {
    default: {
      url: 'https://api.company.local'
    }
  }
};

7.3. CORS

Nếu frontend và backend khác domain hoặc khác port, backend cần cho phép origin của Angular.

https://emr.company.local
Không nên cấu hình CORS dạng * cho hệ thống nội bộ có đăng nhập, cookie, token hoặc dữ liệu bệnh án.

8. Log và kiểm tra sau deploy

8.1. Kiểm tra nhanh

  • Mở URL backend: https://api.company.local/swagger hoặc endpoint health check.
  • Mở URL Angular: https://emr.company.local.
  • Đăng nhập thử.
  • F12 → Network → kiểm tra API có lỗi 401, 403, 404, 500 không.
  • Refresh trực tiếp route con của Angular.

8.2. Bật stdoutLog cho ASP.NET Core khi cần debug

Trong web.config backend, tạm bật:

<aspNetCore processPath="dotnet"
            arguments=".\MyApi.dll"
            stdoutLogEnabled="true"
            stdoutLogFile=".\logs\stdout"
            hostingModel="inprocess" />
Chỉ bật stdoutLogEnabled khi cần debug. Sau khi xử lý xong lỗi nên tắt để tránh sinh log quá nhiều.

8.3. Nơi xem log

  • IIS log: C:\inetpub\logs\LogFiles
  • Windows Event Viewer → Windows Logs → Application
  • Log file của ứng dụng nếu có Serilog/NLog/log riêng
  • Browser DevTools → Console / Network

9. Lỗi thường gặp và cách khắc phục

9.1. HTTP Error 500.19 - Internal Server Error

Dấu hiệuIIS báo 500.19, không vào được site, thường hiển thị lỗi liên quan web.config.
Nguyên nhânXML sai, section bị lock, thiếu module, thiếu Hosting Bundle, duplicate config, không đủ quyền đọc file config.
Cách xử lý
  1. Kiểm tra web.config có đúng XML không.
  2. Nếu Angular dùng <rewrite>, kiểm tra đã cài URL Rewrite chưa.
  3. Nếu backend ASP.NET Core, cài đúng .NET Hosting Bundle.
  4. Kiểm tra quyền thư mục cho App Pool Identity.
  5. Xem chi tiết HRESULT trên màn hình lỗi hoặc Event Viewer.

9.2. HTTP Error 404.3 - Not Found

Dấu hiệuIIS không phục vụ được file static như .json, .webmanifest, hoặc file lạ.
Nguyên nhânThiếu Static Content hoặc thiếu MIME type.
Cách xử lý
  1. Bật IIS feature Static Content.
  2. Thêm MIME type trong IIS hoặc web.config.
  3. Kiểm tra file có tồn tại trong thư mục deploy không.

9.3. Angular refresh route bị 404

Dấu hiệuVào trang chủ được, nhưng refresh tại /patient/123 thì báo 404.
Nguyên nhânIIS tìm file/folder thật tên /patient/123, trong khi route này thuộc Angular Router.
Cách xử lý
  1. Cài URL Rewrite.
  2. Thêm rule rewrite về / hoặc /emr/.
  3. Đảm bảo web.config nằm cùng cấp index.html.

9.4. Lỗi 502.5 / 500.30 ASP.NET Core failed to start

Dấu hiệuIIS nhận request nhưng backend không start được.
Nguyên nhânSai connection string, thiếu runtime, lỗi appsettings, lỗi DI, lỗi migration/database, thiếu quyền ghi log.
Cách xử lý
  1. Chạy thử app bằng command line: dotnet MyApi.dll.
  2. Bật stdoutLog tạm thời.
  3. Xem Event Viewer.
  4. Kiểm tra database có truy cập được từ server IIS không.
  5. Kiểm tra biến môi trường ASPNETCORE_ENVIRONMENT.

9.5. Lỗi CORS

Dấu hiệuBrowser Console báo request bị chặn bởi CORS policy.
Nguyên nhânBackend chưa allow domain của Angular.
Cách xử lý
  1. Thêm origin frontend vào cấu hình CORS.
  2. Kiểm tra đúng schema: http khác https.
  3. Kiểm tra đúng port.
  4. Nếu dùng cookie/auth, cần cấu hình credentials đúng.

9.6. Lỗi 401 Unauthorized

Dấu hiệuAPI trả 401 sau khi deploy, dù local chạy bình thường.
Nguyên nhânSai authority URL, issuer, audience, redirect URI, cookie domain, token config hoặc HTTPS.
Cách xử lý
  1. Kiểm tra URL AuthServer/API trong appsettings và Angular environment.
  2. Kiểm tra redirect URI trên Auth Server.
  3. Kiểm tra token issuer có đúng domain production không.
  4. Kiểm tra server time có lệch quá nhiều không.

9.7. Lỗi 403 Forbidden

Dấu hiệuTruy cập site báo Forbidden.
Nguyên nhânKhông có default document, thiếu quyền thư mục, request filtering, authentication config sai.
Cách xử lý
  1. Kiểm tra có index.html trong thư mục Angular không.
  2. Kiểm tra Default Document có index.html.
  3. Cấp quyền Read cho App Pool Identity.
  4. Kiểm tra Anonymous Authentication có bật cho Angular static site không.

9.8. File upload không lưu được

Dấu hiệuAPI upload lỗi 500 hoặc lưu file không thành công.
Nguyên nhânApp Pool không có quyền ghi, sai đường dẫn, ổ đĩa không tồn tại, giới hạn request size.
Cách xử lý
  1. Cấp quyền Modify cho thư mục upload.
  2. Dùng path tuyệt đối như D:\Sites\MyApp\Files.
  3. Kiểm tra dung lượng ổ đĩa.
  4. Tăng giới hạn upload nếu file lớn.

9.9. IIS không truy cập được từ máy khác trong mạng LAN

Dấu hiệuMáy server vào được localhost, máy khác không vào được.
Nguyên nhânFirewall chặn port, binding chỉ localhost, DNS/hosts chưa trỏ, SSL certificate không tin cậy.
Cách xử lý
  1. Mở Windows Firewall cho port 80/443 hoặc port custom.
  2. Binding IIS dùng IP hoặc hostname phù hợp.
  3. Kiểm tra bằng IP trước: http://192.168.1.10.
  4. Nếu dùng hostname nội bộ, cấu hình DNS hoặc file hosts.
  5. Nếu HTTPS nội bộ, cài certificate vào Trusted Root cho máy client.

10. Checklist triển khai

10.1. Checklist Backend

  • Đã build Release.
  • Đã publish đúng folder.
  • Server đã cài .NET Hosting Bundle.
  • App Pool để No Managed Code.
  • Connection string production đúng.
  • CORS allow đúng domain frontend.
  • App Pool có quyền đọc thư mục deploy.
  • App Pool có quyền ghi thư mục log/upload.
  • API chạy được bằng command line.
  • Swagger hoặc health check mở được.

10.2. Checklist Angular

  • Đã build production.
  • Copy đúng thư mục chứa index.html.
  • Environment production trỏ đúng API URL.
  • Nếu deploy subfolder, đã cấu hình --base-href.
  • Đã cài IIS URL Rewrite.
  • Đã thêm web.config rewrite route.
  • Refresh route con không bị 404.
  • Static file JS/CSS tải thành công.

10.3. Checklist bảo mật cơ bản

  • Dùng HTTPS cho frontend và backend.
  • Không để password production trong source code public.
  • Không bật stdout log lâu dài.
  • Không allow CORS * cho hệ thống có dữ liệu nhạy cảm.
  • Không cấp Full Control nếu chỉ cần Read/Modify.
  • Backup appsettings và database trước khi update production.
Quy trình deploy đề xuất: Publish ra thư mục tạm → backup bản đang chạy → stop site/app pool → copy file mới → kiểm tra appsettings → start site/app pool → test health check → test nghiệp vụ chính.
Tài liệu hướng dẫn deploy IIS cho C# / ASP.NET Core và Angular. Có thể chỉnh sửa thêm theo kiến trúc thực tế của dự án.
