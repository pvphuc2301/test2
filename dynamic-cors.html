1 System Architecture

The database-managed CORS solution enables allowed origins to be resolved, validated, and updated dynamically at runtime. No application pool recycle, server restart, or redeployment is required when CORS origins change.

2 Database Schema — CorsOrigins

Origins are stored in the CorsOrigins table inside the auth schema in SQL Server.

auth.CorsOrigins — Column Definitions
Column Type Constraints Description
Id UNIQUEIDENTIFIER PK · NEWID() Unique identifier of the origin record
AppCode NVARCHAR(50) NOT NULL Target application code (e.g. ADMIN, EMR, HRM)
Origin NVARCHAR(300) NOT NULL Absolute allowed origin URL (e.g. https://admin.timtamduc.local)
Environment NVARCHAR(50) NULL Target environment (e.g. Production, Development)
IsActive BIT NOT NULL · 1 State of the origin. Inactive origins are ignored at runtime.
Description NVARCHAR(500) NULL Optional developer-friendly description
CreationTime DATETIME2 NOT NULL · GETDATE() Creation timestamp (auto-populated)

3 Backend Implementation

Cache-Aside Store CorsOriginStore.cs

Handles allowed origin retrieval with a 5-minute IMemoryCache absolute expiration to prevent querying the database on every request.

Cache Hit

Returns cached origin list directly from memory. Zero database I/O.

Cache Miss

Queries SQL Server, populates cache, resets TTL to 5 minutes.

Resilience Fallback If SQL Server is down or unreachable, the store catches the exception, logs a warning, and falls back to Cors:FallbackOrigins in appsettings.json to prevent a global API service interruption.

Custom Policy Provider DatabaseCorsPolicyProvider.cs

Implements ICorsPolicyProvider to build CorsPolicy dynamically at runtime from the cached origin list.

Allow credentials
Any header
Any method
Security Constraint — Never combine AllowAnyOrigin() with AllowCredentials() This is insecure and rejected by modern browsers. The provider always passes the exact list of cached origin strings via .WithOrigins(origins) rather than using a wildcard.

4 Admin API Reference

All endpoints require administrative rights and OIDC tokens verified under the Admin.FullAccess policy (ConfigAdminController.cs).
GET /api/configadmin/cors List all origins
Returns a list of CorsOrigin JSON objects ordered by creation time.
POST /api/configadmin/cors Create origin

Validation: Enforces absolute URI — must start with http:// or https:// with a valid hostname.

Side effects: Calls _corsStore.InvalidateCache() immediately. Writes audit log.

Request Body 
{
  "appCode": "EMR",
  "origin": "https://emr.timtamduc.local",
  "environment": "Production",
  "isActive": true,
  "description": "EMR Production Frontend"
}
PUT /api/configadmin/cors/{id} Update origin
Request body identical to creation. Invalidates cache immediately and writes audit log.
DELETE /api/configadmin/cors/{id} Remove origin
Invalidates cache immediately and writes audit log.
POST /api/configadmin/cors/clear-cache Invalidate cache

Explicitly invalidates the cache key cors-origins. Writes audit log.

Response
{"message": "CORS memory cache cleared successfully."}

Lists App Code, Origin, Environment, Active Status, Description, and Creation Time.

Regex URL Validation

Modal form blocks submission if the origin isn't a valid absolute URL — validates protocol, host, and bans trailing slashes.

Instant Cache Clearing

Clicking Clear Cache triggers immediate invalidation, forcing a fresh database pull on the next client request.

Audit Log Feed

Every add, edit, delete, or cache clear updates the Audit Logs tab (e.g. ADMIN_CREATE_CORS_ORIGIN, ADMIN_CLEAR_CORS_CACHE).

6 Verification & Diagnostics

Administrators can verify CORS policy evaluation using curl.exe preflight requests directly from PowerShell.

Test Authorized Origin

PowerShell 
curl.exe -i -X OPTIONS http://localhost:8089/api/configadmin/cors `
  -H "Origin: http://localhost:4200" `
  -H "Access-Control-Request-Method: GET"
Expected Response 
HTTP/1.1 204 No Content
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET
Access-Control-Allow-Origin: http://localhost:4200
Vary: Origin

Test Unauthorized Origin

PowerShell 
curl.exe -i -X OPTIONS http://localhost:8089/api/configadmin/cors `
  -H "Origin: http://example.com" `
  -H "Access-Control-Request-Method: GET"
Expected Response 
HTTP/1.1 204 No Content
(No Access-Control-Allow-Origin header)
(No Access-Control-Allow-Credentials header)

→ Browser blocks the request automatically.
How to interpret the results An authorized origin returns Access-Control-Allow-Origin and Access-Control-Allow-Credentials headers, confirming the browser will permit the cross-origin request. An unauthorized origin returns a bare 204 with no CORS headers — the browser silently blocks the response.
