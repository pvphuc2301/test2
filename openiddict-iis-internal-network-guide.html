Cấu hình OpenIddict trên IIS cho mạng nội bộ

Hướng dẫn xử lý lỗi CryptographicException: Access is denied khi chạy AuthServer/OpenIddict trên IIS.

Kết quả tìm kiếm

1 Mô tả lỗi

Khi deploy ứng dụng ASP.NET Core sử dụng OpenIddict lên IIS, hệ thống phát sinh lỗi sau:

Stack Trace 
System.Security.Cryptography.CryptographicException: Access is denied.
at System.Security.Cryptography.X509Certificates.X509Store.Open(OpenFlags flags)
at Microsoft.Extensions.DependencyInjection.OpenIddictServerBuilder
    .AddDevelopmentEncryptionCertificate(...)

Lỗi thường xuất hiện khi request đi qua các endpoint xác thực sau:

/connect/authorize
/connect/token
/connect/introspect

2 Nguyên nhân

Trong cấu hình hiện tại, ứng dụng đang sử dụng hai hàm phát triển mặc định:

Program.cs 
options.AddDevelopmentEncryptionCertificate()
       .AddDevelopmentSigningCertificate();

Hai hàm này cần truy cập vào Windows Certificate Store. Khi chạy dưới IIS, App Pool Identity thường không có quyền mở certificate store hoặc private key, dẫn đến lỗi Access is denied.

Không nên dùng khi deploy IIS Không sử dụng AddDevelopmentEncryptionCertificate() và AddDevelopmentSigningCertificate() khi deploy lên IIS, kể cả trong mạng nội bộ.

3 Giải pháp nhanh cho mạng nội bộ

Nếu hệ thống chỉ dùng trong mạng nội bộ và đang ở giai đoạn test, có thể dùng Ephemeral Key — key được tạo trong bộ nhớ RAM và không cần quyền truy cập Certificate Store.

Program.cs 
if (builder.Environment.IsDevelopment())
{
    options.AddDevelopmentEncryptionCertificate()
           .AddDevelopmentSigningCertificate();
}
else
{
    options.AddEphemeralEncryptionKey()
           .AddEphemeralSigningKey();
}

options.DisableAccessTokenEncryption();
Lưu ý quan trọng Ephemeral Key được tạo trong bộ nhớ. Khi restart IIS/App Pool, key sẽ thay đổi và token cũ có thể không còn hợp lệ. Người dùng có thể phải đăng nhập lại.

4 Cấu hình OpenIddict hoàn chỉnh đề xuất

Dưới đây là cấu hình đầy đủ được khuyến nghị khi deploy lên IIS nội bộ, bao gồm các endpoints, flows, scopes và token lifetimes.

Program.cs — AddOpenIddict() 
builder.Services.AddOpenIddict()
    .AddCore(options =>
    {
        options.UseEntityFrameworkCore()
               .UseDbContext<ApplicationDbContext>();
    })
    .AddServer(options =>
    {
        // Endpoints
        options.SetAuthorizationEndpointUris("/connect/authorize")
               .SetTokenEndpointUris("/connect/token")
               .SetEndSessionEndpointUris("/connect/endsession")
               .SetIntrospectionEndpointUris("/connect/introspect");

        // Flows
        options.AllowAuthorizationCodeFlow()
               .AllowRefreshTokenFlow()
               .RequireProofKeyForCodeExchange();

        // Scopes
        options.RegisterScopes(
            OpenIddictConstants.Scopes.OpenId,
            OpenIddictConstants.Scopes.Email,
            OpenIddictConstants.Scopes.Profile,
            OpenIddictConstants.Scopes.Roles,
            OpenIddictConstants.Scopes.OfflineAccess,
            "api"
        );

        // Token lifetimes
        options.SetAccessTokenLifetime(TimeSpan.FromMinutes(
            builder.Configuration.GetValue<int>("Auth:AccessTokenLifetimeMinutes", 15)));

        options.SetRefreshTokenLifetime(TimeSpan.FromDays(
            builder.Configuration.GetValue<int>("Auth:RefreshTokenExpiryDays", 30)));

        options.SetIdentityTokenLifetime(TimeSpan.FromMinutes(60));

        // Signing & Encryption — dùng Ephemeral khi chạy trên IIS nội bộ
        if (builder.Environment.IsDevelopment())
        {
            options.AddDevelopmentEncryptionCertificate()
                   .AddDevelopmentSigningCertificate();
        }
        else
        {
            options.AddEphemeralEncryptionKey()
                   .AddEphemeralSigningKey();
        }

        // Không mã hóa Access Token để các API khác có thể validate
        options.DisableAccessTokenEncryption();

        options.UseAspNetCore()
               .EnableAuthorizationEndpointPassthrough()
               .EnableTokenEndpointPassthrough()
               .EnableEndSessionEndpointPassthrough()
               .EnableStatusCodePagesIntegration()
               .DisableTransportSecurityRequirement();
    })
    .AddValidation(options =>
    {
        options.UseLocalServer();
        options.UseAspNetCore();
    });

5 So sánh các lựa chọn

Ba phương án cấu hình certificate có các đặc điểm khác nhau tùy theo môi trường và nhu cầu sử dụng.

Bảng so sánh phương án
Cách cấu hình Phù hợp Ưu điểm Nhược điểm
AddDevelopment... Local / Visual Studio Dễ dùng khi phát triển Dễ lỗi quyền trên IIS, không nên dùng khi deploy
AddEphemeral... Mạng nội bộ, test, demo Không cần certificate, chạy nhanh trên IIS Restart app làm token cũ mất hiệu lực
AddSigningCertificate Nội bộ production Ổn định, restart không mất token Cần quản lý file certificate và password

6 Cấu hình Production với Certificate .pfx

Nếu AuthServer phục vụ thực tế cho nhiều ứng dụng như EMR, HRM, Report — cần dùng certificate dạng file .pfx để đảm bảo token ổn định sau khi restart server.

1. Khai báo certificate trong Program.cs

Program.cs 
options.AddEncryptionCertificate(new X509Certificate2(
    @"D:\Certificates\openiddict-encryption.pfx",
    builder.Configuration["Auth:Certificates:EncryptionPassword"],
    X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
));

options.AddSigningCertificate(new X509Certificate2(
    @"D:\Certificates\openiddict-signing.pfx",
    builder.Configuration["Auth:Certificates:SigningPassword"],
    X509KeyStorageFlags.MachineKeySet | X509KeyStorageFlags.EphemeralKeySet
));

2. Cấu hình appsettings.Production.json

appsettings.Production.json 
{
  "Auth": {
    "AccessTokenLifetimeMinutes": 15,
    "RefreshTokenExpiryDays": 30,
    "Certificates": {
      "EncryptionPassword": "your-encryption-cert-password",
      "SigningPassword": "your-signing-cert-password"
    }
  }
}
Khuyến nghị cho hệ thống thực tế Với hệ thống nội bộ dùng thực tế, nên dùng certificate .pfx thay vì Ephemeral Key để đảm bảo token ổn định sau khi restart server. Lưu password certificate trong biến môi trường hoặc Secret Manager, không ghi cứng vào file.

7 Lưu ý về HTTPS trong mạng nội bộ

Hiện tại code có cấu hình cho phép bỏ qua yêu cầu HTTPS:

Program.cs 
options.UseAspNetCore().DisableTransportSecurityRequirement();

Cấu hình này cho phép chạy qua HTTP, phù hợp khi test bằng IP nội bộ:

http://192.168.1.10:5000

Rủi ro khi dùng HTTP

Cookie phiên, authorization code và refresh token truyền qua HTTP có thể bị nghe lén trong môi trường mạng không tin cậy.

Khuyến nghị

Nếu AuthServer phục vụ nhiều ứng dụng nội bộ, nên cấu hình HTTPS với certificate nội bộ (self-signed hoặc CA nội bộ).

8 Checklist sau khi sửa

Thực hiện lần lượt các bước sau để xác nhận hệ thống hoạt động đúng sau khi áp dụng cấu hình mới.

1

Đổi phương thức certificate

Thay AddDevelopment... sang AddEphemeral... hoặc certificate .pfx.

2

Publish lại AuthServer

Build và deploy lại toàn bộ project lên thư mục IIS.

3

Restart IIS App Pool

Recycle hoặc restart App Pool để áp dụng cấu hình mới hoàn toàn.

4

Kiểm tra endpoint Discovery

Mở /connect/.well-known/openid-configuration để xác nhận server phản hồi đúng.

5

Test login từ Angular frontend

Thực hiện luồng đăng nhập đầu cuối từ ứng dụng client để xác nhận token được cấp thành công.

Nếu dùng Ephemeral Key

Yêu cầu user đăng nhập lại sau mỗi lần restart app vì token cũ sẽ không còn hợp lệ.

9 Kết luận

Chọn phương án phù hợp với nhu cầu thực tế của hệ thống:

Test / Demo

Dùng AddEphemeralEncryptionKey() và AddEphemeralSigningKey() để chạy nhanh trên IIS không cần certificate.

Chạy thật (Production)

Dùng certificate .pfx riêng biệt cho signing và encryption để token ổn định và không bị mất khi server restart.

Không nên dùng

AddDevelopmentEncryptionCertificate() khi deploy lên IIS vì sẽ gây lỗi quyền truy cập certificate store.
