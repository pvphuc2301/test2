Tài liệu Admin API & Portal

Tài liệu kỹ thuật chi tiết dành cho nhà phát triển hệ thống Identity & Authorization Server. Hướng dẫn toàn diện về bảo mật, quản trị người dùng, cấu hình OIDC Clients và kiểm soát phiên làm việc.

Tổng quan kiến trúc

Core Framework

Hệ thống được xây dựng trên nền tảng **ASP.NET Core Web API** kết hợp với **OpenIddict** để quản lý các luồng đăng nhập và cấp phát token OAuth2/OpenID Connect. Toàn bộ thông tin tài khoản, mật khẩu, và bảo mật hai lớp (MFA) được quản lý bởi **ASP.NET Core Identity** kết hợp cơ sở dữ liệu **Microsoft SQL Server**.

Các cơ chế bảo vệ chính

Sử dụng các tiêu chuẩn an toàn cao nhất: **Proof Key for Code Exchange (PKCE)** cho luồng Authorization Code Flow, cơ chế tự động khóa tài khoản khi nhập sai nhiều lần, và hệ thống **Custom Session Middleware** giúp giám sát và thu hồi token tức thì khi có yêu cầu từ phía quản trị viên.

Các tham số OpenID Connect phát hành mặc định

Tham số Endpoint / Giá trị Mô tả
Authorization Endpoint /connect/authorize Yêu cầu cấp mã Code xác thực (User login)
Token Endpoint /connect/token Trao đổi Code lấy Access Token & Refresh Token
EndSession Endpoint /connect/endsession Đăng xuất người dùng và hủy session OIDC
Introspection Endpoint /connect/introspect Kiểm tra thông tin chi tiết và trạng thái của Access Token
Token Lifetime Access Token: 15m | Refresh Token: 30d Thiết lập thời gian hết hạn qua cấu hình hệ thống

Bảo mật & Session Middleware

Thông thường, các token Access Token (JWT) được lưu ở Client không thể bị hủy cho tới khi chúng hết hạn. Điều này tạo ra rủi ro nghiêm trọng khi một tài khoản bị lộ thông tin hoặc bị Admin vô hiệu hóa. Để xử lý vấn đề này, AuthServer áp dụng một cơ chế **Middleware kiểm tra Session hoạt động**.

Luồng kiểm tra bảo mật Session (Custom Middleware)

  • Mỗi Access Token do hệ thống phát hành sẽ mang một Claim đặc biệt tên là sid (Session ID) đại diện cho phiên làm việc tương ứng trong DB.
  • Trong mỗi API request được gửi đến Backend, middleware sẽ chặn lại để lấy giá trị sid này.
  • Hệ thống thực hiện kiểm tra thực tế trong bảng UserSessions. Nếu phiên làm việc có trạng thái IsActive = false hoặc đã bị **Revoked** bởi Admin, middleware lập tức phản hồi mã lỗi **401 Unauthorized** cùng thông báo: "The session has been revoked.".
  • Bằng cách này, ngay khi Quản trị viên kích hoạt chức năng khóa tài khoản hoặc thu hồi session trên Admin Portal, tất cả các Client sử dụng token cũ sẽ lập tức bị đá đăng xuất.

Các chính sách phân quyền (Authorization Policies)

Policy Name
Admin.FullAccess

Yêu cầu Claim permissions = Admin.FullAccess. Quyền hạn tối cao thực hiện tất cả cấu hình hệ thống, quản lý OIDC Clients, vai trò, xóa/vô hiệu hóa tổ chức.

Policy Name
User.Create / User.Update

Quyền hạn cấp trung cho phép quản trị viên vận hành tạo và sửa thông tin người dùng, cài đặt thông tin cá nhân mà không thể thao tác các cấu hình máy chủ OIDC.

Các tác vụ khác trên User

PUT /api/users/{id}

Cập nhật họ tên, vai trò mặc định và tổ chức liên kết.

Policy: User.Update
PATCH /api/users/{id}/activate

Kích hoạt hoặc Vô hiệu hóa tài khoản. **Đặc biệt:** Khi gửi giá trị isActive = false, tất cả token và session hiện hoạt của người dùng sẽ bị thu hồi ngay lập tức.

Policy: User.Update
POST /api/users/{id}/reset-password

Đặt lại mật khẩu trực tiếp từ Quản trị viên (Không yêu cầu mật khẩu cũ). Hủy toàn bộ phiên đăng nhập hiện hoạt để đảm bảo an toàn.

Policy: Admin.FullAccess
POST /api/users/{id}/mfa

Bắt buộc bật hoặc cho phép tắt chức năng xác thực 2 lớp (MFA/2FA).

Policy: Admin.FullAccess

Quản lý liên kết Tổ chức của Người dùng

Hỗ trợ mô hình đa tổ chức (Multi-Tenant). Một người dùng có thể thuộc nhiều tổ chức khác nhau với vai trò và phòng ban tương ứng.

GET /api/users/{id}/tenants Lấy danh sách các Tenant được gán
POST /api/users/{id}/tenants Gán một Tenant mới, cho phép chọn vai trò, phòng ban và đặt làm mặc định (Default)
DELETE /api/users/{id}/tenants/{tenantId} Hủy gán người dùng khỏi một Tenant

Quản lý Clients OIDC

Clients

Danh mục API dùng để đăng ký các ứng dụng kết nối (web, mobile, service) được quyền truy cập vào AuthServer. Cấu hình các đặc quyền bảo mật dựa trên chuẩn cấu trúc OpenIddict.

GET /api/clients
Policy: Admin.FullAccess

Lấy danh sách tất cả các ứng dụng đã đăng ký trên máy chủ OIDC.

    "redirectUris": ["http://localhost:4200/signin-oidc"],
    "postLogoutRedirectUris": ["http://localhost:4200/"],

Policy: Admin.FullAccess

Quy tắc ràng buộc đặc biệt khi sửa / xóa vai trò

  • **Không được đổi tên:** Hệ thống cấm tuyệt đối việc đổi tên vai trò Admin thành tên khác để tránh lỗi phá vỡ phân quyền hệ thống.
  • **Không được xóa:** Vai trò Admin không thể bị xóa dưới bất kỳ hình thức nào.
  • **Đang được sử dụng:** Một vai trò đang có bất kỳ người dùng nào được gán vào thì không thể xóa (Hệ thống sẽ trả về mã lỗi **400 Bad Request** kèm thông báo số lượng người dùng đang gán vai trò đó). Bạn cần chuyển đổi vai trò của những người dùng này trước khi xóa vai trò.

Các hành động thu hồi quyền truy cập (Revocation)

Tác vụ Endpoint Cơ chế hoạt động
POST /api/admin/sessions/{id}/revoke Thu hồi một phiên làm việc cụ thể. IP và trình duyệt tương ứng sẽ bị ép đăng xuất ngay lập tức.
POST /api/admin/sessions/user/{userId}/revoke-all Thu hồi toàn bộ phiên làm việc của người dùng chỉ định.
POST /api/admin/tokens/{id}/revoke Thu hồi trực tiếp token của OpenIddict.
POST /api/admin/tokens/user/{userId}/revoke-all Thu hồi tất cả token của một người dùng.
POST /api/admin/tokens/client/{clientId}/revoke-all Thu hồi toàn bộ token đã cấp cho một ứng dụng cụ thể (Ví dụ: khi phát hiện rò rỉ token phía Client).

Xử lý Sự cố & Diagnostics

Trouble Shoot

Tập hợp các API chẩn đoán nhanh lỗi tích hợp OIDC, phân tích cấu hình ứng dụng và truy dấu nhật ký lỗi nhằm hỗ trợ đội ngũ vận hành System Operator.

GET /api/admin/troubleshooting/search-user
Policy: Admin.FullAccess

Tìm kiếm nhanh tài khoản người dùng theo email, số điện thoại hoặc username (Giới hạn tối đa 10 dòng kết quả để bảo mật thông tin).

query - Chuỗi tìm kiếm.
GET /api/admin/troubleshooting/analyze-client/{clientId}
Policy: Admin.FullAccess

Hệ thống thực hiện phân tích cấu hình OIDC của ứng dụng để phát hiện các lỗ hổng hoặc cấu hình sai sót phổ biến.

Response (200 OK)

  "displayName": "Mobile Public Client",
  "clientType": "public",
  "issues": [
    "No Redirect URIs configured.",

  "isHealthy": false

GET /api/admin/troubleshooting/error-logs
Policy: Admin.FullAccess

Quét nhanh danh sách lịch sử các lỗi kết nối của OIDC client, phục vụ gỡ rối trong quá trình tích hợp.

type - Phân loại lỗi, nhận giá trị: redirect_uri, invalid_client, hoặc invalid_grant.
