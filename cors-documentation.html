⚠️ CORS Policy Blocked

CORS Error & Proxy Solution

Detailed post-mortem and resolution for development API requests

📊 Incident Summary

While running the frontend application locally on http://localhost:4200, API calls made to the GraphQL backend endpoint at https://192.168.20.21/api/graphql were blocked by the browser.

🚨
Blocked Error Message:
"Access to fetch at 'https://192.168.20.21/api/graphql' from origin 'http://localhost:4200' has been blocked by CORS policy: Response to preflight request doesn't pass access control check: No 'Access-Control-Allow-Origin' header is present on the requested resource."

To solve this without modifying backend server headers immediately, we configured an Angular CLI Development Proxy. This routes backend calls locally through node, bypassing the browser's origin restrictions.

🔍 Why CORS Blocks Local Development

CORS (Cross-Origin Resource Sharing) is a browser security mechanism designed to prevent malicious scripts on one origin (e.g., local server) from reading sensitive data from another origin (e.g., your backend server).

When the Angular application (origin: http://localhost:4200) requests data from the backend (origin: https://192.168.20.21), the browser performs a Preflight request (an HTTP OPTIONS request) to check if the server permits cross-origin traffic from localhost.

Because the backend did not return the Access-Control-Allow-Origin: http://localhost:4200 header, the browser blocked the response, throwing a console error.

🛠️ Dev Server Proxy Setup

We introduced a local developer proxy. Instead of sending absolute requests to the IP address directly, the Angular application sends relative requests to its own origin (/api/graphql). The Angular dev-server (Node) intercepts this request and proxies it directly to the backend.

✓
Benefit: The browser sees a request to http://localhost:4200/api/graphql (same origin), so CORS restrictions do not trigger. Node then issues the backend request server-to-server.
proxy.conf.json (Project Root) 
{
  "/api": {
    "target": "https://192.168.20.21",
    "secure": false, // Allows self-signed certificates
    "changeOrigin": true, // Changes host header to backend target
    "logLevel": "debug"
  }
}
angular.json (Configuration) 
// under architect > serve > options
"options": {
  "proxyConfig": "proxy.conf.json"
}

🚀 Steps to Run and Verify

  • 1
    Verify Dev Environment Variable

    Ensure that src/environments/environment.development.ts points to the relative path:

    export const environment = {
  production: false,
  graphqlUrl: '/api/graphql'
};
  • 2
    Restart Angular Dev Server

    The dev server needs to reload the new configuration. Kill any running server and start it again:

    npm run start
  • 3
    Validate Network Logs

    Open Developer Tools in the browser, check the Network tab. You will see requests going to http://localhost:4200/api/graphql returning successful status codes (200 OK).
