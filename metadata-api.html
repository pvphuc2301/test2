Meta CMS Backend

v1.0 Documentation

Nội dung

1. Tổng quan hệ thống

Meta CMS Backend là một hệ thống quản trị nội dung mang hơi hướng Low-code/No-code. Thay vì quản lý nội dung dạng bài viết truyền thống, hệ thống quản lý các App, Page, cấu trúc giao diện dưới dạng SchemaJson, và các nguồn dữ liệu động (DataSource, Query).

Cốt lõi
ASP.NET Core, C#, Entity Framework Core (SQL Server)
Giao tiếp API
GraphQL sử dụng thư viện HotChocolate. Hỗ trợ Filtering, Sorting, Projections.
Xác thực & Bảo mật
Tích hợp OpenIddict (OAuth2 / OIDC server nhúng).

2. Mô hình liên kết dữ liệu (ERD)

Cơ sở dữ liệu được tổ chức để lưu trữ cấu trúc ứng dụng đa phiên bản (Versioning) và dữ liệu động.

2.1. Nhóm thực thể Ứng dụng & Giao diện

  • App (Ứng dụng): Đại diện cho một ứng dụng hoặc workspace.
    • Các trường JSON: ThemeJson, VariablesJson, GlobalActionsJson, TemplatesJson. (Cho phép lưu trữ linh hoạt giao diện và biến môi trường của App).
  • AppVersion (Phiên bản App): Quản lý versioning (Semantic Versioning: Major.Minor.Patch) cho App.
    • Lưu trữ SchemaJson toàn cục.
    • Trạng thái: Draft, Published, Archived.
  • Page (Trang): Trực thuộc App (1 App - N Page).
    • Chứa cấu hình PropertiesJson và thông tin định tuyến (Slug, IsHomePage).
  • PageVersion (Phiên bản Trang): Sự kết hợp giữa AppVersion và Page.
    • Mỗi phiên bản App sẽ chốt một SchemaJson (Cấu trúc UI trang) riêng cho trang đó.

2.2. Nhóm thực thể Dữ liệu & Truy vấn

  • DataSource (Nguồn dữ liệu): Điểm kết nối đến DB, API bên ngoài. Lưu trữ cấu hình dạng ConfigJson.
  • Query (Truy vấn): Các script/query gắn với 1 App và 1 DataSource. Được định nghĩa qua QueryConfigJson. Có cờ RunOnMount xác định xem query có chạy ngay khi giao diện được tải hay không.

3. Lớp Giao tiếp GraphQL

Meta CMS sử dụng HotChocolate để bộc lộ dữ liệu qua Endpoint /graphql. Các GraphQL Query chính bao gồm:

// RootQuery.cs hỗ trợ
- GetApps()
- GetAppByName(string name)
- GetPages()
- GetAppVersions()
- GetPageVersions()
- GetDataSources()
- GetQueries()

Tính năng nổi bật

  • Projections, Filtering, Sorting: Cho phép Frontend chỉ truy vấn các trường cần thiết, linh hoạt lọc dữ liệu trực tiếp tại lớp CSDL mà không cần viết thêm mã C#.
  • App Resolvers (AppResolvers.cs): GraphQL tự động tính toán và trả về các trường mở rộng không lưu trực tiếp dạng cột DB, ví dụ: CurrentDraftVersion, PublishedVersion.
  • Ánh xạ JSON động: Các trường VariablesJson và GlobalActionsJson được tự động deserialize thành kiểu AnyType trong GraphQL, giúp Frontend nhận được object thật thay vì chuỗi JSON.

4. Cấu hình & Kết nối Động (ConfigService)

Trong Program.cs, hệ thống thực hiện một quy trình nạp cấu hình mạnh mẽ để lấy chuỗi kết nối (Connection String) từ xa:

  1. Gọi đến AuthServer (Identity Provider) để lấy môi trường của Backend (backend-env?appCode=CMS).
  2. Phân tích JSON trả về để tìm ConfigServiceUrl.
  3. Gọi đến ConfigService cung cấp ClientId, ClientSecret, Environment, và TenantCode để lấy chuỗi kết nối DbContext đã được giải mã động.

Lưu ý: Nếu không gọi được ConfigService, hệ thống có cơ chế Fallback (dự phòng) kết nối đến LocalDB: Server=(localdb)\mssqllocaldb;Database=MetaUI_CMS...

5. Hướng dẫn sử dụng

5.1. Khởi chạy Backend

Backend được cấu hình với CORS mặc định trỏ tới môi trường cục bộ và frontend cụ thể. Khởi chạy bằng .NET CLI:

dotnet restore
dotnet ef database update  # Chạy migration nếu cần
dotnet run

5.2. Tương tác với GraphQL

Khi ứng dụng chạy, bạn có thể truy cập môi trường Banana Cake Pop (GraphQL IDE IDE) qua http://localhost:[port]/graphql.

Ví dụ truy vấn lấy chi tiết một ứng dụng kèm giao diện (Schema) của trang chủ:

query {
  appByName(name: "My App") {
    id
    slug
    variables         # Đã được parse từ JSON -> Object
    globalActions     # Đã được parse từ JSON -> List
    publishedVersion
    pages(where: { isHomePage: { eq: true } }) {
      name
      propertiesJson
      versions {
        schemaJson    # Schema giao diện để render frontend
      }
    }
  }
}
