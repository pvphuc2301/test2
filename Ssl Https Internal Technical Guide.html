Technical Document

Hướng dẫn cài SSL/HTTPS trong mạng nội bộ

Tài liệu này hướng dẫn triển khai HTTPS cho các ứng dụng nội bộ như EMR, HRM, Auth Server, Report Server chạy trên IIS hoặc ASP.NET Core/Kestrel.

Option 1

Self-signed cho môi trường test/lab

Option 2

Internal CA cho bệnh viện/doanh nghiệp

Option 3

Reverse Proxy quản lý SSL tập trung

1. Kiến trúc đề xuất

Với hệ thống nội bộ có nhiều ứng dụng, nên tách domain theo service và dùng một CA nội bộ để phát hành certificate.

Internal Network
│
├── Internal DNS
│   ├── auth.hospital.local  -> 192.168.1.10
│   ├── emr.hospital.local   -> 192.168.1.11
│   ├── hrm.hospital.local   -> 192.168.1.12
│   └── report.hospital.local -> 192.168.1.13
│
├── Internal Root CA
│   ├── auth.hospital.local.crt
│   ├── emr.hospital.local.crt
│   ├── hrm.hospital.local.crt
│   └── report.hospital.local.crt
│
└── Client PCs
    └── Trust Root CA certificate

Khuyến nghị

Dùng Internal CA + Internal DNS + HTTPS binding trên IIS. Đây là hướng ổn định cho EMR/AuthServer nội bộ.

Không khuyến nghị

Không nên dùng IP trực tiếp như https://192.168.1.10 vì khó phát hành certificate đúng chuẩn và dễ lỗi browser trust.

2. Chuẩn domain và DNS nội bộ

Mỗi ứng dụng nên có hostname rõ ràng. Certificate phải khớp với hostname người dùng truy cập.

Ứng dụng Domain đề xuất IP ví dụ

EMRemr.hospital.local192.168.1.11
HRMhrm.hospital.local192.168.1.12
Reportreport.hospital.local192.168.1.13

Cấu hình hosts file khi chưa có DNS Server

# File: C:\Windows\System32\drivers\etc\hosts

192.168.1.11 emr.hospital.local
192.168.1.12 hrm.hospital.local
192.168.1.13 report.hospital.local

3. Cách nhanh: Self-Signed Certificate

Phù hợp cho test nhanh trên IIS hoặc máy dev. Mỗi máy client phải import certificate vào Trusted Root.

Tạo certificate bằng PowerShell

New-SelfSignedCertificate `
  -DnsName "emr.hospital.local" `
  -CertStoreLocation "cert:\LocalMachine\My" `
  -KeyExportPolicy Exportable `
  -KeyLength 2048 `
  -HashAlgorithm "SHA256" `
  -NotAfter (Get-Date).AddYears(3)

Export PFX cho server

$cert = Get-ChildItem -Path cert:\LocalMachine\My | Where-Object {$_.Subject -like "*emr.hospital.local*"}
$pwd = ConvertTo-SecureString -String "YourStrongPassword123!" -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath "C:\certs\emr.hospital.local.pfx" -Password $pwd

Export CER cho client trust

Export-Certificate -Cert $cert -FilePath "C:\certs\emr.hospital.local.cer"

4. Cách chuẩn: Internal CA bằng OpenSSL

Internal CA giúp client chỉ cần trust Root CA một lần, sau đó có thể phát hành nhiều certificate cho nhiều service nội bộ.

4.1. Tạo Root CA

mkdir C:\internal-ca
cd C:\internal-ca

openssl genrsa -out rootCA.key 4096

openssl req -x509 -new -nodes -key rootCA.key -sha256 -days 3650 -out rootCA.crt \
  -subj "/C=VN/ST=HCM/L=HCM/O=Hospital Internal CA/OU=IT/CN=Hospital Root CA"

4.2. Tạo file cấu hình SAN cho EMR

# File: emr-san.cnf
[req]
default_bits = 2048
prompt = no
default_md = sha256
req_extensions = req_ext
distinguished_name = dn

[dn]
C = VN
ST = HCM
L = HCM
O = Hospital
OU = IT
CN = emr.hospital.local

[req_ext]
subjectAltName = @alt_names

[alt_names]
DNS.1 = emr.hospital.local
DNS.2 = emr
IP.1 = 192.168.1.11

4.3. Tạo private key và CSR

openssl genrsa -out emr.hospital.local.key 2048

openssl req -new -key emr.hospital.local.key -out emr.hospital.local.csr -config emr-san.cnf

4.4. Ký certificate bằng Root CA

openssl x509 -req \
  -in emr.hospital.local.csr \
  -CA rootCA.crt \
  -CAkey rootCA.key \
  -CAcreateserial \
  -out emr.hospital.local.crt \
  -days 825 \
  -sha256 \
  -extensions req_ext \
  -extfile emr-san.cnf

4.5. Convert sang PFX cho IIS/Kestrel

openssl pkcs12 -export \
  -out emr.hospital.local.pfx \
  -inkey emr.hospital.local.key \
  -in emr.hospital.local.crt \
  -certfile rootCA.crt

5. Cấu hình HTTPS trên IIS

  1. Mở IIS Manager.
  2. Chọn server node, mở Server Certificates.
  3. Chọn Import, trỏ tới file .pfx.
  4. Chọn website cần cấu hình.
  5. Vào Bindings... → Add.
  6. Chọn Type: https, Port: 443.
  7. Hostname: emr.hospital.local.
  8. SSL certificate: chọn certificate vừa import.
Lưu ý: Nếu nhiều website dùng chung port 443, cần bật SNI và mỗi website phải có hostname riêng.

web.config redirect HTTP sang HTTPS

<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="Redirect to HTTPS" stopProcessing="true">
          <match url="(.*)" />
          <conditions>
            <add input="{HTTPS}" pattern="off" ignoreCase="true" />
          </conditions>
          <action type="Redirect" url="https://{HTTP_HOST}/{R:1}" redirectType="Permanent" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>

6. Cấu hình HTTPS cho ASP.NET Core/Kestrel

Dùng khi ứng dụng chạy trực tiếp bằng Kestrel hoặc sau reverse proxy.

appsettings.json

{
  "Kestrel": {
    "Endpoints": {
      "Http": {
        "Url": "http://0.0.0.0:5000"
      },
      "Https": {
        "Url": "https://0.0.0.0:5001",
        "Certificate": {
          "Path": "certs/emr.hospital.local.pfx",
          "Password": "YourStrongPassword123!"
        }
      }
    }
  }
}

Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.WebHost.ConfigureKestrel(options =>
{
    options.Configure(builder.Configuration.GetSection("Kestrel"));
});

var app = builder.Build();

app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();
app.Run();

7. Cài Root CA cho máy client

Để browser không báo lỗi certificate, máy client phải tin tưởng Root CA hoặc certificate self-signed.

Cài bằng giao diện Windows

  1. Copy file rootCA.crt hoặc .cer sang máy client.
  2. Double click file certificate.
  3. Chọn Install Certificate.
  4. Chọn Local Machine.
  5. Chọn Place all certificates in the following store.
  6. Chọn Trusted Root Certification Authorities.
  7. Finish và restart browser.

Cài bằng PowerShell Admin

Import-Certificate \
  -FilePath "C:\certs\rootCA.crt" \
  -CertStoreLocation "Cert:\LocalMachine\Root"

8. Lưu ý cho Auth Server/OpenIddict

Auth Server nên luôn chạy HTTPS vì liên quan cookie, token, redirect URI và SSO.

Redirect URI

Phải dùng HTTPS và đúng domain.

https://emr.hospital.local/auth-callback

Cookie Secure

Cookie đăng nhập nên bật Secure, SameSite phù hợp.

Cookie.SecurePolicy = Always

Ví dụ domain hệ thống

Auth Server: https://auth.hospital.local
EMR UI:      https://emr.hospital.local
HRM UI:      https://hrm.hospital.local
Report UI:   https://report.hospital.local
API:         https://api.hospital.local

9. Troubleshooting

Browser báo Not Secure / NET::ERR_CERT_AUTHORITY_INVALID

Nguyên nhân thường là client chưa trust Root CA. Cài rootCA.crt vào Trusted Root Certification Authorities.

NET::ERR_CERT_COMMON_NAME_INVALID

Hostname truy cập không nằm trong SAN của certificate. Phải tạo cert có DNS.1 = emr.hospital.local.

Không truy cập được từ máy khác trong LAN

Kiểm tra Windows Firewall, IIS binding, DNS/hosts file, và app có listen trên IP nội bộ không.

Login OpenIddict bị loop

Kiểm tra HTTPS, redirect URI, issuer URL, cookie Secure/SameSite, CORS và reverse proxy header.
