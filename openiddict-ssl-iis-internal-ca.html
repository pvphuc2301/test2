1. Cần tạo bao nhiêu OpenIddict client?

Với các ứng dụng HRM, EMR, Report và CMS, nên tạo client riêng cho từng frontend. Backend API thông thường không cần client nếu chỉ nhận access token từ frontend. Backend chỉ cần cấu hình scope hoặc audience tương ứng.

Ứng dụng Frontend client API scope/resource
HRMhrm-webhrm-api
EMRemr-webemr-api
Reportreport-webreport-api
CMScms-webcms-api

Tối thiểu

hrm-web
emr-web
report-web
cms-web

Tổng: 4 frontend clients.

Khi backend gọi lẫn nhau

hrm-service
emr-service
report-service
cms-service

Tổng có thể thành 8 clients: 4 web clients + 4 service clients.

2. Cần tạo bao nhiêu SSL certificate?

Có hai cách triển khai phổ biến: mỗi hostname một certificate, hoặc dùng một wildcard certificate cho toàn bộ subdomain nội bộ. Với hệ thống nội bộ, wildcard certificate giúp giảm số lượng certificate cần quản lý.

Cách 1: Mỗi hostname một cert

1 Root CA
1 cert cho auth.timtamduc.local
1 cert cho emr.timtamduc.local
1 cert cho hrm.timtamduc.local
1 cert cho report.timtamduc.local
1 cert cho cms.timtamduc.local

Tổng: 6 certificate.

Cách 2: Root CA + Wildcard

1 Root CA
1 wildcard certificate: *.timtamduc.local

Tổng: 2 certificate. Đây là cách khuyến nghị cho hệ thống nội bộ nhiều subdomain.

3. Tạo Root CA và Wildcard SSL certificate bằng OpenSSL

Lưu ý: thay timtamduc.local bằng domain nội bộ của bạn. Không chia sẻ file rootCA.key và wildcard.key ra ngoài.

3.1. Tạo cấu trúc thư mục

mkdir C:\certs
mkdir C:\certs\rootCA
mkdir C:\certs\wildcard

3.2. Tạo Root CA private key

cd C:\certs\rootCA
openssl genrsa -out rootCA.key 4096

3.3. Tạo Root CA certificate

openssl req -x509 ^
-new ^
-nodes ^
-key rootCA.key ^
-sha256 ^
-days 3650 ^
-out rootCA.crt

Thông tin ví dụ khi OpenSSL hỏi:

Country Name: VN
State: HCM
Organization Name: Tam Duc
Common Name: Tam Duc Internal Root CA

3.4. Tạo wildcard private key

cd C:\certs\wildcard
openssl genrsa -out wildcard.key 2048

3.5. Tạo CSR cho wildcard

openssl req ^
-new ^
-key wildcard.key ^
-out wildcard.csr

Khi nhập Common Name, dùng:

*.timtamduc.local

3.6. Tạo file SAN config

Tạo file:

C:\certs\wildcard\san.txt

Nội dung file:

authorityKeyIdentifier=keyid,issuer
basicConstraints=CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names

[alt_names]
DNS.1 = *.timtamduc.local
DNS.2 = timtamduc.local

3.7. Ký wildcard certificate bằng Root CA

openssl x509 ^
-req ^
-in wildcard.csr ^
-CA ../rootCA/rootCA.crt ^
-CAkey ../rootCA/rootCA.key ^
-CAcreateserial ^
-out wildcard.crt ^
-days 825 ^
-sha256 ^
-extfile san.txt

3.8. Tạo file PFX để import vào IIS

openssl pkcs12 ^
-export ^
-out wildcard.pfx ^
-inkey wildcard.key ^
-in wildcard.crt ^
-certfile ../rootCA/rootCA.crt

Sau lệnh này, bạn sẽ nhập password cho file PFX. Password này dùng khi import vào IIS.

4. Import certificate vào Windows/IIS

Root CA

Import file:

rootCA.crt

Vào certificate store:

Certificates (Local Computer)
└── Trusted Root Certification Authorities

Wildcard SSL

Import file:

wildcard.pfx

Vào certificate store:

Certificates (Local Computer)
└── Personal
Quan trọng: khi mở MMC, chọn Computer account, không chọn My user account. Nếu import vào Current User, IIS có thể không thấy certificate.

Nên chọn Personal hay Web Hosting?

Với hệ thống nội bộ chỉ dùng một wildcard certificate cho AuthServer, HRM, EMR, CMS và Report, nên chọn Personal. Store Web Hosting thường dùng cho môi trường hosting lớn có rất nhiều certificate.

6. SNI và cảnh báo “No default SSL site has been created”

Khi nhiều website HTTPS dùng chung một IP và port 443, IIS cần SNI để biết request đang đi tới hostname nào. Vì vậy, mỗi HTTPS binding nên có hostname riêng và bật Require Server Name Indication.

Ví dụ nhiều site dùng chung port 443

auth.timtamduc.local   -> 192.168.1.10:443
emr.timtamduc.local    -> 192.168.1.10:443
hrm.timtamduc.local    -> 192.168.1.10:443
report.timtamduc.local -> 192.168.1.10:443
cms.timtamduc.local    -> 192.168.1.10:443

Cảnh báo IIS

Nếu IIS hiển thị cảnh báo “No default SSL site has been created. To support browsers without SNI capabilities, it is recommended to create a default SSL site”, đây chỉ là cảnh báo khuyến nghị, không phải lỗi.

Với hệ thống nội bộ dùng Windows 10/11, Chrome, Edge hoặc trình duyệt hiện đại, có thể bỏ qua cảnh báo này nếu tất cả site đều bật SNI đúng cách.

Nếu muốn hết cảnh báo

Có thể tạo thêm một fallback/default SSL site:

Site name: DefaultSSL
Binding: https
IP Address: All Unassigned
Port: 443
Host name: để trống
Require SNI: không bật
Certificate: *.timtamduc.local
Khuyến nghị: hệ thống nội bộ hiện đại nên dùng hostname riêng cho từng site và bật SNI. Không nên cấu hình nhiều website HTTPS chung port 443 mà không có SNI.
