Emergency Fallback Auth

Cơ chế đăng nhập dự phòng khi OpenIddict/AuthServer gặp sự cố — đảm bảo hệ thống bệnh viện hoạt động liên tục trong thời gian xử lý sự cố.

Kết quả tìm kiếm

1 Mục tiêu

Emergency Fallback Auth là cơ chế đăng nhập dự phòng được kích hoạt khi OpenIddict/AuthServer gặp sự cố. Hệ thống đảm bảo tính liên tục của dịch vụ y tế mà không làm giảm mức độ bảo mật tổng thể.

Hoạt động bình thường

Người dùng đăng nhập bằng SSO thông qua OpenIddict AuthServer như bình thường.

Khi AuthServer lỗi

Angular tự động phát hiện và hiển thị màn hình đăng nhập dự phòng thay thế.

Chỉ tạm thời

Fallback chỉ dùng trong thời gian xử lý sự cố, không thay thế AuthServer chính thức.

2 Kiến trúc

Hệ thống hoạt động theo hai luồng song song. Mỗi backend ứng dụng phải validate được cả hai loại token: OpenIddict JWT và Fallback JWT.

5 Cấu hình

EmergencyAuth API và tất cả backend ứng dụng (EMR, HRM, Report) phải dùng chung issuer, audience và secret để có thể xác thực token lẫn nhau.

appsettings.json 
{
  "Auth": {
    "Fallback": {
      "Issuer": "Hospital.Internal.EmergencyAuth",
      "Audience": "Hospital.Internal.Apps",
      "AccessTokenMinutes": 15,
      "Secret": "CHANGE_TO_LONG_RANDOM_SECRET_AT_LEAST_64_CHARS",
      "AllowedApps": [ "EMR", "HRM", "REPORT" ],
      "AllowedRoles": [ "EmergencyAdmin", "Doctor", "Nurse" ],
      "AllowedIpRanges": [ "192.168.1.0/24" ]
    }
  }
}
Secret tối thiểu 64 ký tựSử dụng chuỗi ngẫu nhiên đủ độ dài, không dùng password đơn giản.
Không commit productionKhông commit secret production vào source code repository.
Đồng bộ SecretSecret trên EmergencyAuth API và EMR/HRM/Report backend phải giống nhau.

7 Cấu trúc Fallback JWT

Fallback token chứa các claim chuẩn kèm hai claim đặc biệt để phân biệt với OpenIddict token.

JWT Claims Payload 
{
  "sub": "user-id",
  "name": "doctor01",
  "jti": "session-id",
  "role": [ "Doctor" ],
  "auth_mode": "fallback",   // Claim bắt buộc để nhận biết fallback token
  "emergency": "true",
  "app": "EMR"
}
Claim phân biệt bắt buộc Claim auth_mode = "fallback" là bắt buộc. Backend dùng claim này để áp dụng policy NoFallback và chặn các thao tác nhạy cảm.

8 Backend Validate Token

Backend cấu hình hai authentication scheme song song. Token đến từ scheme nào sẽ được validate theo cấu hình tương ứng.

Program.cs — AddAuthentication() 
builder.Services.AddAuthentication()
    .AddJwtBearer("OpenIddict", options =>
    {
        options.Authority = "https://auth.hospital.local";
        options.Audience = "api";
    })
    .AddJwtBearer("FallbackJwt", options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidIssuer = configuration["Auth:Fallback:Issuer"],
            ValidateAudience = true,
            ValidAudience = configuration["Auth:Fallback:Audience"],
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(configuration["Auth:Fallback:Secret"]))
        };
    });

Default Policy — chấp nhận cả hai scheme

Program.cs — DefaultPolicy 
options.DefaultPolicy = new AuthorizationPolicyBuilder(
        "OpenIddict",
        "FallbackJwt")
    .RequireAuthenticatedUser()
    .Build();

9 Giới hạn API nhạy cảm

Fallback token không được phép thực hiện các thao tác admin hoặc rủi ro cao. Sử dụng policy NoFallback để chặn.

Khai báo policy NoFallback

Program.cs 
options.AddPolicy("NoFallback", policy =>
{
    policy.RequireAssertion(context =>
        context.User
               .FindFirst("auth_mode")
               ?.Value != "fallback");
});

Áp dụng lên Controller

UserController.cs 
[Authorize(Policy = "NoFallback")]
[HttpPost("create-user")]
public async Task<IActionResult> CreateUser()
{
    return Ok();
}

Danh sách nên chặn với fallback token:

Quản lý user
Quản lý role/permission
Cấu hình hệ thống
Ký số chính thức
Xóa dữ liệu
Thay đổi danh mục
Thanh toán/quyết toán

10 Angular Flow

Luồng xử lý đăng nhập phía Angular

1

Kiểm tra AuthServer

Angular gọi /.well-known/openid-configuration để kiểm tra trạng thái AuthServer.

✓

AuthServer OK → SSO Login

Redirect sang OpenIddict PKCE flow như bình thường.

✗

AuthServer lỗi → Emergency Login

Chuyển hướng sang /emergency-login.

2

Đăng nhập fallback

User nhập username/password, Angular gọi Emergency Auth API.

3

Lưu token vào sessionStorage

Fallback token được lưu vào sessionStorage, không dùng localStorage.

4

Gọi API với Bearer token

Mọi request gắn header Authorization: Bearer <token>.

Hiển thị banner Emergency Mode

"Bạn đang dùng chế độ đăng nhập dự phòng. Một số chức năng sẽ bị giới hạn."

11 Quy trình bật Emergency Mode

Không nên tự động bật hoàn toànCần có xác nhận thủ công từ IT/EmergencyAdmin trước khi kích hoạt fallback mode.
1

IT xác nhận AuthServer lỗi

Kiểm tra log, monitor và xác nhận sự cố thực sự xảy ra trước khi kích hoạt fallback.

2

EmergencyAdmin bật fallback

Tài khoản EmergencyAdmin đăng nhập vào hệ thống quản lý và kích hoạt chế độ khẩn cấp.

3

Nhập lý do kích hoạt

Lý do bắt buộc phải nhập và được ghi vào audit log để phục vụ kiểm toán sau này.

4

Hệ thống ghi log và kích hoạt

Mọi thông tin kích hoạt được ghi nhận đầy đủ: thời gian, người kích hoạt, lý do.

Fallback tối đa 4 giờ

Hệ thống tự động vô hiệu hóa fallback sau 240 phút dù AuthServer chưa phục hồi.

Tắt fallback khi AuthServer phục hồi

Sau khi AuthServer hoạt động trở lại, EmergencyAdmin tắt fallback mode thủ công.

12 Yêu cầu Bảo mật Bắt buộc

Token ngắn hạn

Token chỉ có hiệu lực 15 phút. Không dùng refresh token trong Phase 1.

Audit log đầy đủ

Log mọi lần đăng nhập thành công lẫn thất bại.

Kiểm tra user

Kiểm tra trạng thái active/locked trước khi cấp token.

Giới hạn Role

Chỉ các role được whitelist mới có thể fallback login.

Không lưu localStorage

Fallback token chỉ lưu trong sessionStorage, xóa khi đóng tab.

Chặn thao tác admin

Fallback token không cho phép thực hiện các thao tác admin nhạy cảm.

Secret JWT bảo mật

Secret phải dài, ngẫu nhiên và được quản lý qua secret store hoặc environment variable — không hardcode trong source code.
