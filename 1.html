Tài liệu Chi tiết về ConfigSafe Admin Portal

Giải pháp Quản lý Tập trung & Mã hóa Chuỗi kết nối, Tham số Cấu hình Bảo mật cho Hệ thống Doanh nghiệp.

Kết quả tìm kiếm

1 Tổng quan về ConfigSafe

Trong các kiến trúc hệ thống hiện đại (microservices, đa người thuê - multi-tenant), việc quản trị tập trung cấu hình và bảo mật các thông tin nhạy cảm như chuỗi kết nối cơ sở dữ liệu (connection strings), API Keys và Credentials là một thách thức lớn.

ConfigSafe ra đời nhằm giải quyết vấn đề lộ lọt tài nguyên hệ thống bằng cách mã hóa toàn bộ dữ liệu cấu hình nhạy cảm dưới database và chỉ thực hiện giải mã trực tiếp trong bộ nhớ hệ thống (in-memory) khi có yêu cầu hợp lệ từ các Client Web API được ủy quyền.

Loại bỏ Clear-Text Password

Không lưu trữ thông tin đăng nhập thô trong mã nguồn, file cấu hình cục bộ (appsettings.json, .env).

Quản lý Tập trung & Phân vùng

Quản lý tất cả chuỗi kết nối phân tách theo từng ứng dụng, môi trường (Prod, Staging, Dev) và Tenant (Khách hàng/Chi nhánh).

Ủy quyền Granular khắt khe

Định nghĩa tường minh ứng dụng khách nào (Client App) được quyền đọc tài nguyên kết nối nào thông qua bảng ánh xạ phân quyền.

Kiểm toán Truy cập Toàn diện

Mọi hành động đọc, giải mã hoặc thay đổi cấu hình đều được ghi nhận dấu vết (Audit log) kèm thông tin định danh, IP, User Agent.

Lưu ý quan trọng Trang Admin Portal này hoạt động như một trung tâm quản lý cấu hình và kiểm toán (Configuration & Audit Center). Chỉ những tài khoản có vai trò Admin (được xác thực thông qua Central Identity Server) mới được cấp quyền truy cập.

2 Kiến trúc Bảo mật & Luồng Dữ liệu

Hệ thống ConfigSafe vận hành dựa trên cơ chế **"Zero Plain-text Storage"** và **"Least Privilege Access"**.

Cơ chế Mã hóa & Bảo mật

Mã hóa AES-256

Khi cấu hình được ghi thêm mới thông qua Admin Portal, server sử dụng thuật toán mã hóa đối xứng AES với khóa Master Key độ dài 256-bit được quản trị nghiêm ngặt ở cấp hệ thống để mã hóa dữ liệu đầu vào.

Giải mã In-Memory

Chuỗi kết nối sau khi lưu trữ sẽ không bao giờ xuất hiện dưới dạng thô trên ổ đĩa. Khi Client API yêu cầu, dữ liệu được tải vào RAM, giải mã và trả về qua kênh TLS (HTTPS), sau đó Client API lưu cache tạm thời.

Phân quyền Xác thực

Sử dụng hai lớp xác thực riêng biệt: Lớp xác thực người dùng cho Portal Admin thông qua OIDC PKCE flow; Lớp xác thực dịch vụ (M2M) dùng Client Credentials và xác nhận quyền trong cơ sở dữ liệu.

3 Quản lý Ứng dụng (Applications)

Mục này cho phép người quản trị đăng ký, cập nhật thông tin và kiểm soát trạng thái hoạt động của các Client Web API tham gia truy xuất cấu hình. Mỗi ứng dụng đăng ký sẽ tương ứng với một định danh Client duy nhất trong hệ thống.

Cấu trúc Dữ liệu Ứng dụng (ConfigApp)
Thuộc tính Kiểu dữ liệu Mô tả chi tiết
code string Mã ứng dụng viết hoa (Ví dụ: EMR, HRM, REPORT). Dùng để ánh xạ quyền.
name string Tên mô tả tường minh (Ví dụ: Electronic Medical Record).
apiClientId string Mã định danh Client ID gửi qua headers khi gọi API lấy chuỗi kết nối.
apiClientSecret string (Write-only) Mật khẩu API Client Secret thô (chỉ được hiển thị một lần duy nhất lúc tạo mới). Hệ thống sẽ băm (hash) mật khẩu này bằng thuật toán an toàn trước khi ghi xuống Database.
isActive boolean Trạng thái ứng dụng. Nếu đặt là false, mọi truy xuất từ Client này sẽ ngay lập tức bị từ chối.
Mẹo bảo mật Khi tạo mới ứng dụng, hệ thống hỗ trợ nút Generate Secret tạo ngẫu nhiên chuỗi bảo mật 16 ký tự an toàn. Hãy đảm bảo bạn sao chép chuỗi này và cấu hình cho Client App ngay lập tức vì hệ thống sẽ mã hóa và băm chuỗi này nên không thể đọc lại từ cơ sở dữ liệu.

4 Quản lý Chuỗi kết nối (Connections)

Đây là phân hệ lưu trữ thông tin nhạy cảm nhất. Giao diện cho phép tạo lập các chuỗi kết nối phân bổ theo App Code sở hữu, Tenant Code cụ thể và Môi trường.

1. Cơ chế phân mảnh chuỗi kết nối

Để hỗ trợ đầy đủ kiến trúc Multi-tenancy và CI/CD Pipeline, mỗi chuỗi kết nối được phân chia theo ba chiều:

  • App Code: Xác định cơ sở dữ liệu này thuộc sở hữu của phân hệ nào (Ví dụ: Database của phân hệ EMR).
  • Tenant Code: Xác định dữ liệu kết nối này thuộc về khách hàng hoặc chi nhánh cụ thể nào (Ví dụ: Chi nhánh bệnh viện BV001). Nếu dùng chung cho tất cả các bên, trường này được cấu hình là Default (Global) (giá trị lưu dưới cơ sở dữ liệu là null).
  • Environment: Xác định môi trường chạy ứng dụng. Gồm 3 tùy chọn: Production, Staging, và Development.

2. Quy trình Giải mã & Kiểm toán (Decryption & Auditing)

Tại danh sách chuỗi kết nối trên giao diện, mật khẩu và chi tiết chuỗi kết nối thô sẽ hiển thị dạng ẩn chấm tròn để tránh lộ mật khẩu trong các tình huống quay phim, chụp màn hình hoặc chia sẻ màn hình.

Khi quản trị viên có quyền nhấn nút Decrypt:

1

Gửi Yêu cầu Giải mã Bảo mật

Frontend gửi một request HTTPS POST tới endpoint /api/configadmin/connections/{id}/decrypt kèm token xác thực quản trị viên.

2

Giải mã In-Memory tại Backend

Backend dùng khóa hệ thống giải mã chuỗi từ Database, ghi nhận tức thời hành động này thành một bản ghi DECRYPT_CONNECTION vào Audit Log.

3

Trả về Kết quả & Hiển thị

Phần mềm nhận chuỗi kết nối thô, hiển thị hộp thoại cho phép copy và lưu trữ tạm trong bộ nhớ cục bộ của Component Angular (không lưu localStorage).

5 Phân quyền chi tiết (Permissions)

Đây là rào chắn phân quyền quan trọng nhất của ConfigSafe. Một Client App (được xác thực thông qua Client ID/Secret) **chỉ có thể truy xuất chuỗi kết nối** nếu có một bản ghi phân quyền tương ứng cho phép truy xuất.

// Ví dụ về logic kiểm tra quyền tại Backend khi EMR API yêu cầu kết nối:
if (clientApp.code === "EMR" && targetAppCode === "EMR" && connectionName === "Default") {
AllowReadConnection(); // Thành công
} else {
ThrowForbiddenException(); // Bị từ chối (HTTP 403)
}

Quyền được Khai báo (Whitelisted)

Cho phép các luồng xử lý liên thông. Ví dụ: Report API được cấp quyền đọc chuỗi kết nối của cả hai phân hệ EMR và HRM để làm báo cáo tổng hợp.

Chặn Mặc định (Default-Deny)

Bảo vệ ngăn ngừa xâm nhập chéo. Nếu kẻ tấn công chiếm được thông tin đăng nhập của EMR API, chúng cũng không thể gửi yêu cầu lấy chuỗi kết nối cơ sở dữ liệu nhân sự của HRM API.

6 Nhật ký Kiểm toán (Audit Trail)

Mọi sự kiện mang tính bảo mật đều được ghi lại tức thì vào bảng Audit Log để phục vụ mục đích rà soát, đối chiếu khi xảy ra sự cố bảo mật (Security Auditing). Các trường dữ liệu kiểm toán bao gồm:

Hành động (Action)

Phân loại sự kiện: GET_CONNECTION_SUCCESS, GET_CONNECTION_DENIED, DECRYPT_CONNECTION, CREATE_APP.

Nhân tố Thực hiện (Client ID / User)

Ghi nhận rõ thao tác đó được thực hiện bởi Lập trình viên quản trị hệ thống (ví dụ: PhucPV) hay bởi API của ứng dụng khách (ví dụ: emr-api).

Địa chỉ IP & Thiết bị (IP Address / UA)

Lưu trữ IP nguồn gửi yêu cầu để phát hiện các request bất thường từ dải IP lạ bên ngoài mạng nội bộ.

Kết quả & Lý do (Result & Reason)

Ghi nhận trạng thái: Success hoặc Failed cùng nguyên nhân từ chối (ví dụ: Client secret invalid).

7 Live Simulator (Giả lập Yêu cầu bảo mật)

8 Cấu hình môi trường thời gian chạy (Environment Config)

Phân hệ này cho phép lập trình viên ghi đè (override) các địa chỉ URL dịch vụ, máy chủ định danh hoặc Client ID trực tiếp trên trình duyệt của mình mà không cần thay đổi tệp tin mã nguồn tĩnh environment.ts.

Các khóa cấu hình lưu trữ trong trình duyệt:

configsafe_env_override Lưu đè cấu hình cho Admin Portal (API Base URL, OAuth Server URL...)
configsafe_env_override_emr Lưu đè địa chỉ API và máy chủ OIDC của phân hệ EMR Frontend
configsafe_env_override_report Lưu đè địa chỉ Máy chủ Báo cáo (Report Engine Host URL)

Khi thay đổi các giá trị này và nhấn Save Environment Override, ứng dụng Angular sẽ ghi dữ liệu vào localStorage và tự động làm mới trang (reload) để khởi tạo lại toàn bộ HttpClient và OIDC Service với các cấu hình mới.

9 Hướng dẫn Triển khai Phát triển (Dev Setup)

Dự án Admin Portal chạy trên framework **Angular v21.2.0** với trình quản lý package **npm v11.11.0**. Hãy làm theo các bước dưới đây để thiết lập môi trường phát triển dưới máy tính cá nhân.

1. Các lệnh khởi động cơ bản

Terminal / Bash 
# 1. Di chuyển vào thư mục dự án
cd admin-portal
# 2. Cài đặt các thư viện phụ thuộc (dependencies)
npm install
# 3. Khởi chạy máy chủ phát triển (Development Server)
npm run start
# hoặc
ng serve

Sau khi máy chủ khởi chạy thành công, ứng dụng sẽ chạy trên cổng mặc định tại địa chỉ http://localhost:4200/.

2. Chạy Kiểm thử & Build

Chạy Unit Test với Vitest

Dự án sử dụng Vitest thay cho Karma cũ để thực hiện test nhanh chóng hơn. 

npm run test

Build Product Bundle

Biên dịch tối ưu hóa tài nguyên tĩnh lưu trữ vào thư mục dist/. 

npm run build

10 Cơ chế xác thực liên hợp OIDC PKCE

Để đảm bảo an toàn tuyệt đối cho hệ thống quản trị, Admin Portal tích hợp tiêu chuẩn xác thực **OpenID Connect (OIDC)** kết hợp cơ chế bảo vệ mã hóa **Proof Key for Code Exchange (PKCE)** để chống lại các cuộc tấn công đánh chặn Authorization Code.

Luồng xác thực diễn ra như sau:

1

Sinh mã khóa bí mật Code Verifier

Khi admin nhấn đăng nhập, Angular sử dụng thư viện mã hóa của trình duyệt (window.crypto) tạo ra chuỗi ngẫu nhiên dài 56 ký tự gọi là **Code Verifier**.

2

Tạo Code Challenge & Chuyển hướng

Code Verifier được băm SHA-256 rồi mã hóa dạng Base64url để tạo thành **Code Challenge**. Trình duyệt chuyển hướng người dùng đến máy chủ Auth Server với các tham số: Client ID, Redirect Callback URI, Scope và Code Challenge.

3

Trao đổi Mã token và đối chiếu Code Verifier

Sau khi xác thực tài khoản thành công tại Auth Server, trình duyệt chuyển hướng quay lại Admin Portal kèm tham số code. Angular Portal gửi POST request chứa mã này kèm **Code Verifier** thô đã lưu trong trình duyệt. Auth Server tự băm Code Verifier thô này để đối chiếu với Code Challenge đã nhận ở Bước 2. Nếu khớp, Auth Server trả về Access Token JWT.

Cấu hình tập tin môi trường mẫu:

src/environments/environment.ts 
export const environment = {
  production: false,
  apiBaseUrl: 'http://localhost:8082/api',
  authServerUrl: 'http://localhost:8082',
  clientId: 'angular-spa',
  redirectUri: 'http://localhost:4200/auth/callback',
  postLogoutRedirectUri: 'http://localhost:4200/'
};
